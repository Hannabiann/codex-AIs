# Восстановление объектов из KOD в 0.28

KOD — двоичный снимок одного объекта: внутренний номер, атрибуты и включённые в них потоки. В штатной форме kodweb выбирается один файл, затем том для записи. Rust сохраняет этот режим и добавляет восстановление нескольких файлов с общей проверкой перед записью.

## Как открыть

**P → Закачать .kod → Восстановить несколько файлов .kod — предварительный список**.

Прямой адрес: `/20a?ispravlenieForm&codex_restore=1`. Нужны права доступа к административному каталогу.

1. Выберите файлы `.kod` и один доступный для записи том.
2. Нажмите «Проверить файлы». На этом этапе база не изменяется.
3. Проверьте номер, область, имя, совпадения с базой и столбец «Связанные объекты». Новые объекты отмечены; существующие требуют отдельного выбора. Полностью совпадающие записи пропускаются.
4. При выборочном восстановлении нажмите «Добавить связанные файлы», чтобы отметить недостающие зависимости из загруженного набора. «Проверить связи выбранных» обновляет сведения без записи.
5. Для замены отметьте нужные строки и «Разрешить замену выбранных существующих объектов по номеру или имени». Нажмите «Восстановить выбранные объекты».

Одноимённая запись в выбранной области тома заменяется по правилам штатной формы. Если её номер отличается от восстанавливаемого, прежний номер удаляется; таблица показывает его до подтверждения. Несколько одноимённых записей или совпадение номера с объектом другой области запрещают восстановление этой строки. Номер, видимый в другом подключённом томе, также показывается и требует разрешения; сам другой том не изменяется.

## Связанные объекты

Проверяются исходящие атрибуты-ссылки каждого файла. Для каждой связи показаны номер атрибута, внутренний номер объекта и его состояние: есть в подключённой базе, находится в выбранном файле, файл ещё не выбран или объект отсутствует. Собственный служебный номер объекта не считается связью. Повторы одной ссылки объединяются только в справочном списке; в восстанавливаемых данных порядок и повторы сохраняются.

«Добавить связанные файлы» проходит цепочки ссылок среди загруженных файлов, включая циклы. Добавляются только недостающие объекты, которые можно восстановить без замены. Уже существующие объекты и строки с конфликтами автоматически не отмечаются. Обратные ссылки не обходятся; файлы с диска не подгружаются сами.

В строке показаны первые десять связей. Ссылка «Все ссылки» открывает полный список по 100 на страницу. Общая сводка относится к выбранным объектам и последней проверке. Отдельно отмечаются ссылки на номера, удаляемые из выбранного тома при замене по имени.

Перед сохранением доступность объектов проверяется повторно. Если смена выбора или изменение базы создали новые отсутствующие ссылки, запись откладывается: форма сохраняет отметки и показывает обновлённый список. Можно добавить недостающие файлы или повторно подтвердить восстановление с этими ссылками. Номера не переназначаются, пустые объекты вместо отсутствующих не создаются. Возможность сохранить такую ссылку соответствует штатному импорту kodweb.

Проверка связей — состояние на момент чтения, а не блокировка всех подключённых томов. Она не гарантирует, что другой запрос не удалит связанный объект позже. Транзакция записи по-прежнему охватывает только выбранный том.

## Запись и конфликты

Заголовок KOD, границы полей, внутренний номер и типы атрибутов проверяются до формирования списка. Нельзя выбрать произвольный путь вместо подключённого тома. Повреждённый файл не приводит к частичному импорту остальных файлов запроса.

Пакет может содержать несколько вариантов одного объекта. Строки с одинаковым внутренним номером либо одинаковым именем в одной области первоначально не отмечены. В «Совпадениях среди файлов» доступны ссылки на сравнение в отдельной вкладке, чтобы сохранить ещё не отправленный выбор. У каждого файла есть номер строки, поэтому различаются и файлы с одинаковыми именами.

Сравнение показывает отличающиеся атрибуты по 25 на страницу. Порядок и повторы значений учитываются. Для просмотра приводятся первые три значения атрибута и первые 160 символов строки. Текст и двоичные вложения сравниваются полностью, но в таблице показан только размер: одинаковый размер не означает одинаковое содержимое. Совпавшие данные отмечены отдельно. Порядок загрузки файлов не определяет, какая редакция новее.

Выбор варианта снимает отметки с непосредственно конкурирующих файлов. Например, если A совпадает с B по номеру, а B с C по имени, A и C могут быть выбраны вместе, если между ними нет совпадения. Сервер повторяет проверку: при несовместимом наборе возвращает список с сохранёнными отметками без записи. Разрешение замены существующих объектов не отменяет эту проверку.

«Добавить связанные файлы» не выбирает редакцию при нескольких вариантах и не отмечает файлы с совпадающим именем. После ручного выбора проходит связи именно выбранного варианта. Невыбранный объект, уже имеющийся в базе, остаётся доступным для ссылок из базы.

### Сравнение с базой и последствия замены

В колонке «Состояние в базе» есть ссылки «Сравнить с записью в томе». Они открывают отличия от существующей записи по номеру и от одноимённой записи с другим номером. Сравнивается снимок выбранного тома на момент подготовки списка. Если объект изменился позднее, запись по такому списку отклоняется; для актуального сравнения нужно сформировать его заново. Записи из других томов эта таблица не сравнивает.

При выборе замены по имени появляется таблица «Последствия замены по имени»: прежний номер, новый номер и число ссылок из выбранных файлов. Нажатие на число открывает сами источники и номера атрибутов, по 100 на страницу. Повторы одной пары «атрибут — номер» внутри одного файла считаются один раз только для просмотра; в данных сохраняются все повторы.

Проверяются ссылки из выбранных файлов пакета. Это не поиск всех обратных ссылок в базе. Ссылки на удаляемый номер не переписываются на новый; их сохранение соответствует штатному импорту kodweb. Можно снять замену, выбрать другой снимок или подтвердить восстановление после просмотра последствий.

Если замена удалит номер, который одновременно восстанавливается из другого выбранного файла, эта пара несовместима, даже когда имена файловых объектов различаются. Форма показывает причину и предлагает оставить один вариант. Прямая отправка несовместимого набора возвращает список с сохранёнными отметками без записи. Та же проверка остаётся в writer.

Подтверждение связано с пользователем и подготовленным списком и действует 30 минут. Списки хранятся в памяти; просроченные удаляются при следующем запросе просмотра или подтверждения. После перезапуска файлы нужно выбрать заново. «Отменить список» освобождает его. Повтор успешно выполненного подтверждения возвращает прежний результат без записи.

Предварительный список и результат открываются отдельными GET-запросами после перенаправления HTTP 303. Можно открыть карточку объекта, вернуться кнопкой «Назад» и обновить результат без повторной отправки файлов или сохранения. Ссылка на список остаётся доступна только подготовившему его пользователю с административными правами и действует в пределах тех же 30 минут.

Внутри блокировки writer повторно читаются записи выбранного тома. Совпадения по имени, запись по номеру и отметка удаления должны соответствовать предварительному списку. Если они изменились, пакет отклоняется. Удаление прежних одноимённых записей и вставка выбранных объектов входят в один проверенный образ DB4. Публикация использует существующий журнал восстановления или замену полного файла при большом объёме изменений.

Атомарность относится к **одному пакету в одном томе**. Несколько подтверждений или разные тома не образуют общей транзакции. До фиксации журнал восстанавливает прежнее состояние, после — весь пакет.

## Проверка с kodweb

Проверено 25 ноября 2026 года на полном контрольном комплекте с 49 объявленными томами. Использованы отдельные контрольные объекты, один с внутренним текстом и двоичным вложением. Это проверка формата и поведения, а не замер восстановления реального дела.

|---|---|
| Три исходных файла в штатной форме kodweb и одним пакетом Rust | Все три объекта записаны |
| Штатная форма одного файла в Rust, `/20a?ispravlenieForm&bkod=1` | Два объекта восстановлены отдельными загрузками; карточки открылись, текст сохранён, двоичное вложение совпало побайтно |
| Чтение итогов Rust в kodweb | Открылись пять карточек после всей серии; двоичное вложение совпало побайтно, текст читается |
| Одно имя, разные номера | Требуется разрешение; прежний номер заменён |

Дополнительное сравнение замены по имени: Rust и штатный импорт kodweb удалили прежний номер и одинаково сохранили ссылки на него — как в выбранном файле, так и в существующем объекте вне пакета. Проверено изменение существующей записи с тем же номером, сравнение с предварительным снимком и отказ записи после постороннего изменения. В локальных целевых тестах выбора и связей прошли 13 проверок, включая все страницы 205 источников. Новые страницы проверены HTTP-запросами; полный обход обратных ссылок базы не выполняется.

Сохраняется известное различие: kodweb добавляет повтор служебного атрибута 1024 и при компиляции внутреннего текста может дописать пробел. Rust оставляет одно поле номера и не добавляет пробел. Пользовательские атрибуты и двоичные данные проверяются отдельно от этих различий.

Выбор редакций проверен пятью целевыми тестами, HTTP-запросами и исполнением обработчиков галочек из полученного HTML. На полном комплекте Rust восстановил восемь выбранных контрольных объектов, включая штатную загрузку одного файла. kodweb прочитал их; отдельный импорт тех же файлов в kodweb дал те же имена и ссылки. Повторно прошли проверки связанных пакетов, старой пакетной формы и восстановления после семи прерываний записи. Новые страницы сравнения в этом проходе проверялись через HTTP; повторного прогона кликами в Edge не было.

Для проверки связей дополнительно прошли четыре целевых теста и HTTP-сценарии выбора зависимостей, повторного подтверждения, исчезновения объекта между просмотром и записью, постраничного просмотра и проверки прав. Штатный импорт kodweb отдельно выполнил восстановление тех же четырёх контрольных файлов; исходные ссылки совпали. Проверки новых кнопок в этом проходе выполнялись через HTTP, без повторного прогона в Edge.

В локальном наборе прошли 532 обычных теста; 117 проверок с отдельными условиями не запускались общим прогоном. Дополнительно выполнены три целевые проверки KOD, в том числе восстановление отметки удаления, конкурирующие записи и семь стадий прерывания журнала. После перезапуска Rust прочитал те же карточки и вложения. Проверка в Edge завершена: выбор нескольких файлов, предварительный список, выборочное восстановление и открытие карточек. Найденная при возврате из карточки ошибка `ERR_CACHE_MISS` исправлена и повторно проверена в браузере. HTTP-проверки перенаправлений, повторного подтверждения, отменённого списка и отказа анонимному запросу прошли; контрольная сумма DB4 при этих повторных просмотрах не изменилась.

## Границы реализации

- До 256 файлов в запросе размером до 64 МиБ. До 16 предварительных списков с общим бюджетом данных 128 МиБ.
- Один том на пакет. Автоматического выбора исходного тома для каждого файла нет.
- Исполняемые KS не импортируются: совместимый компилятор не реализован. Области 5, 8, 900, 901, 1002, 1003, 1010 и области участников 7410–7412 исключены из пакетной формы.
- Внешние файлы, отсутствующие внутри KOD, не восстанавливаются. Ссылки на отсутствующие объекты не создают их автоматически.
- Проверка конфликтов относится к выбранному тому. Номера и ссылки KOD сохраняются; новые номера не назначаются.
- Writer пока формирует образ тома в памяти. Пакет сокращает число публикаций, но расход памяти зависит от размера тома.

## Разработчику

`kod_restore.rs` отвечает за форму, хранилище списков, права и подтверждение. `kod_choices.rs` сопоставляет конкурирующие файлы и показывает отличия; проверка уникальности выбранных номеров и имён остаётся также в writer. `kod_links.rs` хранит все варианты каждого номера, проверяет исходящие ссылки, выбирает зависимости и формирует страницы. Каждый связанный номер проверяется один раз за проход через метаданные DB4, без чтения текста и вложений. `http_form.rs` разрешает несколько бинарных полей `filekod` только на этом маршруте; старый маршрут сохраняет запрет повторов. Загрузки не подставляются в глобальные переменные KS.

`document_kod.rs` проверяет подключение тома и схему. `writer_kod.rs` разбирает снимки, собирает совпадения и повторяет проверку под блокировкой записи. При изменении writer сохраняйте [порядок фиксации и восстановления DB4](DB40_WRITES.md).
