# Тест электронной подписи через Карму

23 ноября 2026 года, версия 0.25. Проверена серверная часть протокола электронной подписи на полном контрольном комплекте с `kodweb.exe`. Проверка кнопки подписания в Word пока не завершена.

## Окружение и сценарий

Использованы Word 2024, Карма 56.2.937.395277, CAPICOM 2.1.0.2, КриптоПро CSP 5.0.13000 и отдельный самоподписанный сертификат RSA-2048 с программным ключом Microsoft CSP. Наличие КриптоПро проверяет сама надстройка; этот RSA-тест не использует ГОСТ или токен. Вызов `Sign2` повторяет вызов из `spdas.dotm`: отделённая подпись, текстовое представление PKCS#7. В этом окружении Карма выбрала SHA-1 для подписи содержимого; это результат конкретного клиентского вызова, а не выбор алгоритма сервером Rust.

Сначала проверены создание подписи искусственного текста и её передача через `/99?testget` и `/99?getdigsign`. Затем подписан настоящий RTF тестового определения: сохранено состояние карточки, файл прочитан с сервера, подписан Кармой, подпись записана в DB4, выполнен `signdoc`, повторно прочитаны атрибуты, RTF и подпись.

У первого выбранного определения стояла форма «без текста». Kodweb вернул отрицательный признак проверки подписания, хотя файл подписи был сохранён. Итоговый сценарий использует штатную форму документа «с текстом» и проверяет положительный признак `signdoc`.

## Результаты

| Проверка | Kodweb | Rust 0.25 |
|---|---|---|
| Загрузка файла подписи через `testget` | HTTP 204 | HTTP 204 |
| Чтение первой подписи: без `epnum` и с `epnum=0` | Исходные байты | Исходные байты |
| Запрос отсутствующей второй подписи | HTTP 204 | HTTP 204 |
| Итоговое состояние карточки | Блокировка 7, «Подписан ЭП» = 1 | Те же значения |
| Проверка `signdoc` для формы «с текстом» | Успешна | Успешна |
| RTF до и после подписания | Не изменился | Не изменился |
| Криптографическая проверка полученной из DB4 подписи | Успешна | Успешна |
| Загрузка PDF через `savebinpdf` и подписи через `savesigforpdf` | Два ответа HTTP 204 | Два ответа HTTP 204 |

| Криптографическая проверка сохранённого PDF | Успешна | Успешна |

Ответы сохранения карточки, повторного чтения её атрибутов и выдачи RTF совпали побайтно. В успешном ответе `signdoc` отличается регистр логического значения: `True` и `true`.

Проверено чтение в обе стороны: Rust прочитал запись kodweb, затем kodweb прочитал запись Rust. Атрибуты, RTF и сохранённая подпись совпали с ответами сервера, который их записал. Отдельно подтверждён отказ криптографической проверки после изменения подписанного текста.

Для PDF использован файл, сформированный самим Word: 138 589 байт, отделённая подпись — 2 242 байта. Оба сервера сохранили их побайтно. Ссылка «Копия PDF» и связанная запись области «Файл» читаются в обе стороны. Вновь выделенные OID различаются между серверами; сравнивались связи и содержимое, а не равенство новых номеров.

## Исправление сохранения PDF

При первом проходе через кнопку Word подпись RTF сохранилась, а следующий запрос `savebinpdf` завершился 501. Штатный KS этого запроса исполняется в `/99`, но читает `FileDocPath` и месячные хранилища `BasicPath` из `/20a`. Rust учитывал только хранилище текущего каталога.

Исправлены выбор хранилища и доступ к записи для авторизованных PUT/POST `savebinpdf` и `savesigforpdf`. Добавлены используемые этими скриптами операции `File.close()` и SQL `afterLast()`. Закрытие синхронизирует и освобождает файл; все ссылки на закрытый поток перестают принимать запись. Переход `afterLast()` ставит курсор после последней строки, чтобы `prev()` выбрал запись для подписи, без повторного выполнения SQL.

После исправления автоматические проверки кода: 478 успешно, 86 пропущены. Отдельно проверены запрет записи без авторизации, ограничение каталогами хранилища, закрытие общих ссылок на файл и позиция курсора пустого и непустого SQL-результата.

## Что эта проверка не подтверждает

Самоподписанный сертификат не имеет доверенной цепочки. Карма создаёт подпись, но её обычная проверка сообщает о недоверенном корне. Математическая корректность CMS проверена отдельно через `SignedCms.CheckSignature(true)`, без проверки доверия к сертификату. Это не положительная проверка доверенной или квалифицированной подписи.

Повторный полный проход через интерфейс Word после исправления PDF не завершён. Первый проход подтвердил создание и сохранение подписи RTF; файл PDF и его подпись были сформированы клиентом, но загрузка PDF выявила описанную выше 501. Серверный повтор обоих PDF-запросов уже успешен.

ГОСТ-подпись, аппаратный токен, доверенная цепочка, отзыв сертификата, штамп времени и коллегиальное подписание этим сценарием не проверены.
