# Общие настройки системы в 0.27

Раздел `/20a?adminsettings` использует формы и обработчики KS из базы. Работают штатные кнопки сохранения, в том числе на странице «Все режимы» (`mode=1&id=3`) и в «Первичной регистрации» (`mode=1&id=4`). Отдельная кнопка «Сохранить только номера» больше не нужна.

## Как сохраняются параметры

Обработчик формы меняет `Application.Config`, свойства каталога и значения встроенного реестра. Rust собирает эти изменения в памяти. После успешного завершения штатного `SaveState` обновляет записи и индексы `config.db4` одной транзакцией. Следующий номер дела и следующий входящий номер сохраняются вместе с остальными полями формы.

Поддержаны `REG_SZ` и `REG_DWORD`, вложенные ключи, удаление значения через `DeleteValue`, строки Windows-1251 длиннее 255 байт. Очистка поля, которому KS присваивает `null`, сохраняет пустой `REG_SZ`, как kodweb. Удаление параметра — отдельная операция.

У прямой записи `RegistryRoot.SetValue` и у `Application.Config`/`SaveState` различается обновление словарного индекса. Это различие воспроизведено по сохранениям оригинала. Для проверенной функции `mp_CReg_setValue` добавлена совместимая строковая запись логических значений: `True` и `False`. Исправление применяется только при совпадении отпечатка функции; явно введённые строки сохраняются без такой замены.

В контрольном `config.db4` встречаются несколько действующих записей одного свойства. `QueryValue` выбирает первую по OID, а перечисление свойств при запуске может вернуть последнюю. При сохранении свойства Rust согласует значения этих записей. Это устраняет возврат старых настроек при следующем запуске, в том числе в kodweb.

На startup штатный сценарий БРАС заполняет пустую «Дату последнего успешного экспорта» значением по умолчанию, даже если обмен отключён. Rust поддерживает эту конкретную инициализацию. Она согласуется между исполнителями и не заменяет уже установленную дату. Как и в оригинале, такая служебная дата сама по себе не подтверждает состоявшийся экспорт.

### Кэш показателей главной страницы — исправление 0.28.3

Штатная библиотека `mp_stats` сохраняет рассчитанный показатель и «Дату последнего обновления» в ветке `Настройки\Статистики сервера` соответствующего каталога в `config.db4`. В 0.28.2 такая запись вне формы администратора могла прервать открытие персональной панели ошибкой `RegistryRoot.SetValue … persistent registry writes are not implemented`.

В 0.28.3 авторизованный запрос главной страницы может сохранять этот кэш. Значение и дата публикуются вместе после успешного исполнения страницы через существующий журнал восстановления DB4. При ошибке запроса подготовленные записи отбрасываются. Если другой исполнитель уже обновил тот же показатель, его значение и дата сохраняются; изменения других настроек объединяются без повторного расчёта. Разрешение ограничено веткой показателей и не открывает произвольную запись конфигурации.

На контрольном полном комплекте проверен показатель «Нераспределённых дел»: ранее HTTP 501, после исправления HTTP 200; HTML совпал с kodweb побайтно. Сохранены штатные типы: `Значение` — `REG_DWORD`, дата — `REG_SZ`. Проверены четыре одновременных запроса и повторное открытие после перезапуска. Отдельная проверка на изолированной копии `config.db4` охватывает длинную строку, создание ключа, отмену записи, конкурирующие обновления одного и разных показателей и сохранение независимого изменения конфигурации.

### Повторяющиеся записи параметров — исправление 0.28.4

Некоторые конфигурации содержат несколько действующих записей одного параметра. Обновление кэша главной страницы увеличивает поколение `config.db4`, после чего исполнители перечитывают настройки распределения дел и календаря. Старый обработчик этого чтения отклонял дубли ошибкой `duplicate registry setting`, хотя основной `RegistryRoot.QueryValue` их поддерживал.

Читатель использует первую запись по OID. Сохранение параметра согласует все его действующие копии с сохранением их OID, имён и родительских связей; явное удаление параметра удаляет все его копии. Остальные параметры не меняются. Проверка устаревшей формы и журнал восстановления сохраняются.

В предоставленном для проверки `config.db4` было две записи `ReestrJudeRaspred`. Исправленный читатель обработал 37 параметров без изменения файла. На изолированной копии проверены сохранение всех дублей, повторное чтение, повторное сохранение без изменений, отказ устаревшей форме и удаление параметра.

На полном контрольном комплекте воспроизведена такая же пара записей. В 0.28.3 обновление показателя проходит, но последующие обращения к главной, личной панели и настройкам распределения возвращают HTTP 501. Kodweb и 0.28.4 возвращают HTTP 200; HTML главной, личной панели и показателя совпал побайтно. В 0.28.4 прошли четыре одновременных обращения и повторная проверка после перезапуска. Из другого суда предоставлен только `config.db4`; HTTP-проверка выполнена на контрольном полном комплекте.

## Проверки

Проверено на полном контрольном комплекте, с отдельными исходными снимками для сохранений kodweb и Rust.

| Проверка | Результат |
|---|---|
| Открытие и сохранение всех разделов меню | 42 формы, включая «Все режимы» |
| Сравнение полей после сохранения | Значения совпали с kodweb во всех 42 формах |
| Сравнение реестра после одинаковых изменений | 2342 действующих параметра: совпали имена, типы и значения |
| Номера, реквизиты и галочки | Проверены оба номера, длинная кириллическая строка, включение и снятие отметок |
| Файловое хранилище | Создание месячного `BasicPath`, выбор нескольких месяцев, удаление прежней привязки и повторное открытие |
| Перезапуск и чтение оригиналом | После сохранения Rust все 42 формы повторно открыты в Rust и kodweb |
| Две формы с одной исходной версией | Одно сохранение успешно; второе получает HTTP 409, оба номера остаются из одной операции |
| Запрос без авторизации или с неверным токеном | Отказ, файл не изменяется |
| Нулевой, отрицательный или слишком большой номер | HTTP 400, файл не изменяется |
| Прерывание записи | Проверены семь этапов журнала и публикации; восстановлены прежние либо полностью новые данные |
| Повреждённый затронутый индекс | Отказ до публикации; незатронутая база остаётся прежней |
| Одновременная инициализация даты БРАС | Четыре исполнителя принимают одно сохранённое значение; запись другой даты его не перезаписывает |

Проверки форм выполнялись HTTP-запросами с полями штатных HTML-форм. Это не проверка всех клиентских JavaScript-обработчиков и не подтверждение работы внешних сервисов. Основной автоматический набор: 496 тестов без ошибок; проверки на полном комплекте выполнялись отдельно.

## Что учитывать

Сохранение требует прав администратора. Форма содержит токен и версию прочитанного файла. Если другой запрос уже изменил конфигурацию, нужно открыть настройки заново; значения не перезаписываются старой вкладкой. Регистрационные номера должны быть целыми числами от 1 до 2147483647.

Параметры доступны исполнителям при следующем запросе. Производные значения, которые KS вычисляет один раз в startup, обновляются после перезапуска. Порт HTTP также применяется при запуске слушателя; `KODEKS_PORT` сохраняет приоритет над `config.db4`.

Сохранение адресов, расписаний и реквизитов SMTP, FTP, БРАС/КАД и других систем не проверяет доступность этих систем и не реализует весь обмен. Отправка сообщений, экспорт в рабочие внешние сервисы, создание произвольных сетевых каталогов и каждый вариант зависимых настроек в эту проверку не входили. Совместимость с иными выпусками KS и схемами конфигурации требует отдельного сравнения.
