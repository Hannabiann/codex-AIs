# Печать наклеек — 0.30

Страница `/20a?sticker` использует штатный KS `sticker` и библиотеку `libsticker`. Сохранены форма kodweb, выбор дела, участников и бланка. Сервер заполняет RTF из базы и отдаёт `sticker.rtf`; открыть и распечатать его можно в Word. Word на сервере для формирования файла не требуется.

## Работа с формой

1. Введите номер дела. Доступны точное совпадение, поиск по части, началу или окончанию номера, а также маска `*`.
2. Если найдено несколько дел, выберите нужное и нажмите «Готово».
3. Укажите предмет иска, отметьте участников и выберите бланк. Можно разделять стороны переносом строки или точкой с запятой, включить дату заседания и названия пустых сторон.
4. Нажмите «Печатать наклейку». Как в kodweb, этот шаг сохраняет в деле предмет спора и номер штрихкода, затем формирует RTF. При вызове из регистрации без поля предмета его прежнее значение сохраняется.

Отдельный штатный режим `forcebarcode_print` формирует `barcode.rtf` без изменения карточки дела.

Список «Бланки» заполняется доступными в текущем разделе объектами области **530 «Бланки»**, название которых начинается с `Наклейка (`. Если список пуст, форма показывает «Нет доступных бланков наклейки». Для печати нужен доступный объект бланка с RTF в поле «Данные» и штатными закладками. Наличие других бланков в комплекте ещё не означает, что они доступны в этом разделе.

В проверенных бланках штрихкод использует шрифт **EanBwrP36Tt**. Он должен быть установлен на компьютере, где открывают и печатают файл; без него вместо полос могут отображаться символы.

## Исправления

- Повторные поля флажков участников принимаются как список индексов, включая индекс `0`. Повторение управляющего параметра `mode` по-прежнему отклоняется.
- Исправлено кодирование цифр штрихкода в проверенной редакции KS. Общая семантика конструктора `Array(length)` не менялась.
- SQL поддерживает соединение двух строковых полей. Это нужно штатной закладке суммы иска, которая связывает дело с заявлением по наименованию.
- Замена закладок RTF поддерживает начало и конец в разных группах форматирования. Сохраняются структура документа, оформление, переносы строк и пустые значения, как в kodweb.
- Кнопка «Отбор» больше не вызывает себя повторно; поиск по Enter работает в современном браузере.
- Проверка штатного ограничения в 50 найденных дел выполняется по идентификаторам до чтения дат и сортировки. На контрольном широком запросе время сократилось с 38,4 до 0,75 с; kodweb — 0,66 с. Это отдельные замеры на том же комплекте, а не нагрузочный тест.

Адаптация исходного текста включается только при совпадении полного отпечатка проверенного KS `sticker`, редакция **47570**. Библиотека `libsticker` — редакция **40186**. Другие редакции требуют отдельного сравнения.

## Проверка совместимости

На полном комплекте с 49 объявленными томами выполнено сравнение с kodweb.exe 5.3.2.120:

- Семь сценариев поиска: точный, по части, началу, окончанию, маске, без результатов и с более чем 50 результатами. Совпали текст, ссылки, состав и порядок выдачи; отметка времени формирования исключена из сравнения.
- Четыре штатных RTF-бланка: «истец/ответчик», «заявитель/заинт. лицо», «заявитель/должник», «заявитель/ответчик». Проверены все участники, выбранная часть участников, оба разделителя, дата заседания, скрытие пустых сторон и отдельный штрихкод. Все **шесть контрольных RTF совпали побайтно**.
- Сохранённые предмет спора и номер штрихкода совпали побайтно в DB4. Kodweb прочитал результат Codex-AIs после перезапуска.
- В Chromium проверены поиск по Enter, выбор дела, возврат, групповое переключение флажков и печать. Ответ на отправленную браузером форму также совпал с RTF kodweb.

В исходном состоянии список бланков был пуст и в kodweb. Печать проверена на временных доступных копиях четырёх штатных бланков с неизменённым содержимым RTF. Проверка не включала физический принтер и считывание штрихкода сканером.

Сборка Windows прошла. Автоматические проверки: **93 пройдены**, 5 с отдельными внешними условиями пропущены.
