# Запуск с настройками другого суда — 0.25.3

## Недоступное файловое хранилище

В 0.21 появился обработчик вложений регистрации. При каждом открытии `File` он разрешал пути всех настроенных хранилищ. Если один из путей ссылался на отсутствующий диск, обход родителей доходил до корня и завершался ошибкой `attachment path has no parent`. Это была ошибка хоста: штатный `catch (...)` в `mp_createFile` её не перехватывал. В результате даже проверка обычного файла могла прервать startup.

В 0.25.3 недоступный или недопустимо широкий каталог не предоставляет доступ к файлам и не мешает обращениям к другим каталогам. Ошибка самого запрошенного пути передаётся как файловое исключение KS с путём и причиной ОС. Штатный `mp_fileExists` может обработать её и вернуть `false`. Отсутствующие вложения не подменяются пустыми файлами; запись требует доступного разрешённого каталога и прежних прав пользователя.

На копии полного комплекта путь вложений `/20a` изменён через реестр оригинального сервера на отсутствующий диск `Z:`. Для трёх запусков использована одна конфигурация:

| Сервер | Открытие `/20a/` |
|---|---|
| kodweb.exe | HTTP 200 |
| codex-AIs 0.25.2 | HTTP 501, `attachment path has no parent` |
| codex-AIs 0.25.3 | HTTP 200; 20 759 байт HTML совпали с kodweb побайтно |

Отдельный тест выполняет штатный `mp_createFile` с существующим файлом и недоступным хранилищем: проверка возвращает `true:false`, после чего журнал успешно записывается. Проверены запрет записи вне хранилища, каталоги, пересекающиеся с корнем базы, и прежние операции загрузки и копирования вложений. Пройдено 487 автоматических тестов. Проверка выполнена на Windows; комплект другого суда и запуск этой сборки на FreeBSD здесь не проверялись.

## Порт HTTP

Порт выбирается при запуске в таком порядке:

1. Явно заданный `KODEKS_PORT`.
2. `Port` в ветке `SOFTWARE\Kodeks\Web` файла `config.db4`.
3. `8070`, если параметра нет.

Некорректное значение вызывает сообщение с источником настройки. Порт в `config.db4` должен быть от 1 до 65535. Изменение настройки требует перезапуска. В 0.25.3 адрес интерфейса задавался через `KODEKS_HOST`, по умолчанию `127.0.0.1`. С 0.28.1 значение по умолчанию — `0.0.0.0`, а выбор localhost и сохранение порта доступны в расширенных настройках: [сеть и порт](BUILD_AND_RUN.md#сеть-и-порт).

В журнале запуска указаны выбранный порт и его источник. `Application.Servers` и `Application.RuntimeListenAddress` используют фактический порт слушателя. Форма `/admin?port` показывает сохранённую настройку оригинального сервера: при переопределении через окружение она может отличаться от фактического порта Rust.

Проверено на полном комплекте: kodweb и Rust прочитали `8181` из одной конфигурации; Rust с `KODEKS_PORT=8282` принял запросы на `8282`. В тестах также проверены отсутствие параметра, границы диапазона, неверные значения и приоритет ручной настройки.

## Сообщение о зависимостях

`83 missing dependencies` означает 83 неразрешённых объявления подключения, а не обязательно 83 разных файла. Один том может упоминаться несколькими каталогами. Это отдельная проверка, не связанная с выбором порта.

Из каталога своего комплекта можно сохранить список подключений командой:

```powershell
.\codex-AIs.exe inspect > volumes.txt
```

Строки `missing` показывают каталог и ожидаемый путь. Они помогают отличить отсутствующие тома от старых необязательных подключений. Исправление файлового хранилища не восстанавливает отсутствующие DB4/DBS.
