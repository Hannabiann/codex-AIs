# Журналы и ежедневные архивы

С 0.29 каталог по умолчанию — `Log-codex-AIS` внутри корня базы. Например, для `C:\kodeks` это `C:\kodeks\Log-codex-AIS`. Каталог создаётся при запуске. Явный `KODEKS_LOG_DIR` сохраняет приоритет; фактическое переопределение показано в `/admin/`.

| Файл или каталог | Содержимое |
|---|---|
| `error.log` | Ошибки HTTP/KS, фоновых заданий, инициализации и необработанные Rust panic |
| `access.log` | Завершённые HTTP-запросы и фоновые операции: адрес клиента, пользователь, исполнитель, маршрут, длительность, результат |
| Остальные `.log` | Журналы штатных KS, перенаправленные из логического `Log`/`log` |
| `OLD_Log/*.zip` | Завершённые дневные сегменты журналов |

`error.log` и `access.log` записываются в UTF-8. Каждая запись занимает одну строку, дата содержит миллисекунды и часовой пояс сервера. Ошибка запроса содержит ID операции, адрес клиента, пользователя, номер исполнителя KS/DB, маршрут, длительность и сообщение интерпретатора с доступной цепочкой вызовов. Обычный ответ 401 при запросе авторизации остаётся в `access.log`, без отдельной ошибки. Незавершённые операции видны в `/admin?status`.

Заголовки Authorization/Cookie и тело формы в серверные журналы не копируются. В URL остаются имена параметров и числовые координаты документа; поисковые строки, пароли и токены скрываются. Само сообщение исключения может содержать диагностические данные приложения. Это текстовая диагностика, а не дамп памяти kodweb.

KS-журналы сохраняют штатную кодировку и содержимое. Для имён `Log/access.log` и `Log/error.log` используются `ks-access.log` и `ks-error.log`, чтобы KS не мог обнулить серверный журнал. Логические файлы в корне базы, например `time.log`, по-прежнему получают префикс `root-`. Старые журналы прежних версий остаются на прежнем месте; новый выпуск не объединяет их автоматически с текущим днём.

## Настройка срока хранения

Откройте **Администрирование → Установки → Расширенные настройки** (`/admin?advanced`). Параметр **«Хранить ZIP-архивы логов, дней»** сохраняется в `codex-AIs.settings`:

```ini
log_retention_days=7
```

Допустимы значения от 0 до 3650. По умолчанию сохраняются архивы за семь предыдущих календарных дней плюс текущие журналы. Например, 26 ноября остаются архивы за 19–25 ноября; более ранние удаляются. Значение **0** отключает удаление архивов по сроку. Изменение применяется после перезапуска, как остальные параметры этой формы.

В `/admin?pref` убраны поля путей и выбора формата протокола kodweb. Вместо них показаны каталог Codex-AIs, назначение журналов и ссылка на расширенные настройки. То же пояснение добавлено на стартовую страницу `/admin/` и в справку установок. Остальные поля штатной формы сохранены.

## Как происходит ротация

1. При смене локальной даты текущие `.log`, включая вложенные KS-журналы, перемещаются в отдельный сегмент внутри `OLD_Log`. Переключение согласовано с записью; следующий вызов уже открытого KS-файла переоткрывает текущий журнал.
2. Отдельный поток сжимает сегмент в ZIP64 с Deflate. Сжатие не занимает исполнителя KS/DB и не удерживает блокировку записи журналов. Файлы читаются порциями по 64 КиБ.
3. Завершённый ZIP синхронизируется с диском и публикуется переименованием временного файла. Исходный сегмент удаляется после публикации. После прерывания сжатия незавершённый сегмент обрабатывается повторно при запуске.
4. По сроку удаляются только архивы с именами, которые формирует этот механизм. Текущие журналы, незавершённые сегменты и произвольно названные пользовательские файлы не удаляются.

Имя архива начинается с даты сегмента, затем содержит уникальный суффикс: `2026-11-25-1234-….zip`. Обычно за день получается один архив; при восстановлении после прерванного переключения возможно несколько сегментов одной даты. Проверка даты происходит перед записью и фоновым потоком раз в 30 секунд. Если сервер был выключен ночью, предыдущий день архивируется при следующем запуске.

Ошибки серверной записи журналов также выводятся в stderr. Если каталог недоступен уже при запуске, причина остаётся в консоли. Серверная запись не удерживает блокировки монитора или DB4. Изменение формата и ротация не меняют протокол записи базы.

## Проверки 0.29

Проверено на Windows x64, на полном контрольном комплекте из 49 томов:

- главная, `/admin?pref`, сведения о программе, справка и расширенные настройки;
- ошибки 404 и KS 500, 24 запроса с восемью параллельными клиентами, сокрытие секретного параметра URL;
- штатные KS-журналы в новом каталоге и явный `KODEKS_LOG_DIR`;
- ошибка запуска при отсутствующем `config.db4` в отдельном тестовом каталоге;
- смена дня при запуске: шесть журналов, в том числе файл 16 МиБ; все байты архивов совпали с исходными файлами;
- сохранение сроков 0 и 2 через штатную форму, применение 2 после перезапуска, граница хранения 7 дней;
- 19 автоматических тестов Rust, включая 800 записей из восьми потоков, четыре потока записи одновременно со сжатием, открытый KS-файл после ротации и повторное сжатие прерванного сегмента;
- независимая распаковка ZIP и проверка CRC через Python `zipfile`, включая кириллические имена.

Новый механизм не добавляет зависимостей от Windows-служб или внешнего архиватора. Проверка исполнения 0.29 на Linux и FreeBSD ещё требуется.
