# Рабочий график суда — 0.21

Раздел `/97` открывает штатную форму `/20a?newJudAndHoliday&`. Разметка, кнопки, список сотрудников и правила календаря берутся из KS-скриптов установленной АИС.

## Работа с календарём

Выберите год и нажмите «Показать календарь». В режиме «Суд в целом» щелчок по дню меняет его тип: рабочий или выходной. Кнопка «Сохранить изменения» записывает результат в область «Календарь» подключённого рабочего тома DB4.

Для просмотра отсутствия сотрудников выберите режим «Судьи» и сотрудников через кнопку с тремя точками. «Зарегистрировать отпуск» открывает штатную форму `makeVacation`: в ней указываются начало, конец и причина отсутствия. Отпуска и отгулы сохраняются в DB4 и отображаются в календаре выбранного сотрудника.

Если календаря на выбранный год ещё нет, выполняется штатный генератор. Он использует выходные и перечень праздничных дат из KS установленного комплекта. Переносы выходных не загружаются из внешних источников: их задают в самом календаре.

## Доступ и арбитражные заседатели

Кнопка «Настройки доступа» находится в форме «Зарегистрировать отпуск». Администратор выбирает сотрудников через классификатор и нажимает «Установить». Список сохраняется в свойстве `AccessByUserForMakeVacation` каталога `/20a` в `config.db4`. Пустой список оставляет доступ только администраторам. Изменения доступны другим исполнителям KS/DB без перезапуска сервера.

В проверенном комплекте список ограничивает редактирование отпусков сотрудников через `makeVacation`. Скрипты календаря `newJudAndHoliday` и заседателей `regassessors` эту настройку не проверяют. Rust сохраняет штатную область действия настройки; считать её общим запретом записи во всём разделе `/97` нельзя.

Для графика заседателя выберите «Арбитражные заседатели» и нажмите «Зарегистрировать отпуск». Открывается штатная форма `regassessors`: имя, признак действующего заседателя, сроки полномочий, примечание и периоды отсутствия. Можно создать запись, изменить существующую, добавить несколько периодов и удалить отдельный период. Записи сохраняются в областях «Арбитражные заседатели» (7828) и «Отпуск» (7822) рабочего тома; периоды связаны с заседателем штатным атрибутом.

## Изменения интерпретатора

- Пустая строка при `split` даёт пустой список, как в штатном KS. Открытие формы без изменённых дат больше не пытается сохранить пустую дату.
- Временный документ со скриптом можно заполнить, скомпилировать и исполнить без выделения постоянного OID. Запись постоянного документа по-прежнему требует блокировки.
- Сгенерированная функция, сохранённая в задании, сохраняет доступ к собственным аргументам после завершения исходного HTTP-запроса.
- Задание создания календаря выполняется в момент ожидания его результата. Оно получает отдельный контекст запроса; исходный контекст восстанавливается при успехе и ошибке. Это устраняет ожидание исполнителем собственной очереди.
- Поле даты принимает числовое значение в миллисекундах. Нестрогое сравнение даты с таким числом сравнивает время; строгое сравнение сохраняет различие типов. Штатный цикл формирования года останавливается на его границе.
- Повторяющиеся `nm_numdoc` и `nm_deldoc` в отпускной форме объединяются в список OID. Повторные управляющие параметры, например `mode`, по-прежнему отклоняются.
- При удалении нескольких строк форма добавляет каждый OID в список удаления. В исходном JavaScript вызов без третьего аргумента заменял предыдущий OID последним.
- `SaveState` формы доступа записывает только её свойство в `config.db4` через существующий механизм журналируемой записи. Штатная проверка прав администратора остаётся в KS.
- Поддержан `Document.Delete` с явным списком томов. Штатный `mp_deleteDocumentFull` различает отсутствие объекта в выбранном томе и запрет записи, затем удаляет период из нужного тома. Индексы и запись обновляются с журналом восстановления.
- В форме заседателей строка исчезает после успешного ответа на удаление. При ошибке она остаётся на экране; сохранение недоступно, пока удаление выполняется. После удаления и добавления строки номера её полей не повторяются.

## Проверка

Проверки выполняются на полном контрольном комплекте с 49 подключёнными томами. Контрольные сценарии: смена рабочего и выходного дня, добавление двух периодов отсутствия, изменение причины и даты окончания, формирование високосного года, чтение данных обоими серверами.

| Проверка | Результат |
|---|---|
| Календарь 2026 года после изменения двух дней | Совпали все 365 дат и их типы |
| Создание календаря 2028 года | Совпали все 366 дат, из них 116 выходных по штатному генератору |
| Записи календаря и отсутствия в рабочем томе | Совпали 119 записей по области, флагам и прикладным полям; OID и служебные атрибуты не сравнивались |
| Чтение результата Rust в kodweb | Прочитаны созданный год, отпуск и отгул с теми же датами |
| Удаление одного периода | В обоих серверах остаётся второй период с неизменными датами и причиной |
| Удаление двух периодов одним сохранением в Rust | После повторного открытия форма не содержит этих периодов |
| Создание заседателя и двух периодов отсутствия | Совпали 3 записи по области, флагам и прикладным полям, а также 28 полей формы |
| Календарь выбранного заседателя | Совпали все 365 дат и их атрибуты разметки |
| Изменение причины, даты окончания и удаление одного периода | После повторного открытия значения совпали с kodweb |
| Добавление периода после удаления строки | Сохранились оставшийся и новый периоды; повторяющихся имён полей нет |
| Удаление всех периодов | После завершения запросов и повторного открытия строк нет; новый период можно добавить |
| Список доступа | Проверены сохранение, очистка, выбор через классификатор и чтение после перезапуска |
| Права в Rust на полном комплекте | Пользователь из списка допущен к форме отпусков; отсутствующий в списке получает отказ; обычный пользователь не может сохранить настройки доступа |
| Чтение результата Rust в kodweb | Прочитаны заседатель, изменённые периоды и список доступа с теми же значениями |

Число 116 характеризует результат скрипта контрольного комплекта, а не утверждённый производственный календарь на 2028 год. Настройки доступа и графики арбитражных заседателей дополнительно проверены 22 ноября 2026 года на том же полном комплекте.

В локальном проверочном проекте прошли 388 автоматических тестов. Дополнительно выполнены проверки ролей на полном комплекте и сравнение сохранённых записей. Проверки покрывают границу года, числовые значения полей дат, временные скрипты, восстановление контекста после ошибки задания, списки удаляемых отпусков, методы запросов с записью и отказ записи в закрытый том.
