# Пустые значения в вычислениях KS: 0.27

В KS пустое значение `null` отличается от числового нуля. Rust раньше преобразовывал его в `0` при большинстве арифметических операций. Из-за этого отсутствующее значение могло становиться числом или приводить к `NaN` — неопределённому числовому результату.

Исправление сохраняет правила штатного интерпретатора для арифметики с `null`:

| Выражение | Результат |
|---|---|
| `null + null`, `null - null` | Пустое значение |
| `null * 2`, `2 * null`, `null * null` | Пустое значение |
| `null / 2`, `null / 0` | Пустое значение |
| `2 / null`, `null / null`, `null % 2` | Ошибка, которую обрабатывает KS через `catch` |
| `null + 2`, `null - 2`, `2 - null` | `2`, `-2`, `2` |
| `0 * 2` | Числовой `0` |
| `null + "текст"` | Строка `"текст"` |

Те же правила применяются к `+=`, `-=`, `*=` и `/=`. Если операция завершается ошибкой, прежнее значение переменной сохраняется. Операнды вычисляются один раз. Явное преобразование `Number(null)` по-прежнему возвращает ноль; отдельные правила денежных значений `LongDouble` не менялись.

Изменение находится в интерпретаторе. Штатные функции построения форм получают пустое значение вместо выдуманного числового результата. Это продолжение исправления [лишней вкладки «Отправка»](DOCUMENT_OPEN_0.27.md).

## Объём проверки

Правила сопоставлены со штатным интерпретатором `kdb.exe`/`kdbdll.dll`: 140 выражений с пустыми значениями и контрольными числами. Совпали тип, значение результата и успешное завершение либо отказ. Текст сообщения об ошибке и её внутренний код не заявляются идентичными.

Четыре регрессионных теста проверяют эту матрицу, сохранение переменной при ошибке, однократное вычисление операндов, явные преобразования, денежные значения и пустые вычисляемые поля формы.

На копии полного комплекта 25 ноября 2026 года сравнены HTML-результаты отчёта о работе суда 1АС (`StatOtchet221`, `act=1`) и нерегламентной статистики Z22.1 (`statNoReglament`, `mode=1`, `act_out=1`) за 1 октября 2026 года. Совпали все 263 и 103 ячейки соответственно. Это сравнение выбранных HTML-разделов, а не всех листов XLS или полного годового отчёта.

Для 13 контрольных документов проверены список вкладок, текст и карточка: все 39 запросов завершились с HTTP 200, содержимое 37 страниц совпало с kodweb. Два различия в карточке дела существовали до изменения арифметики. Они исправлены отдельно в той же версии: [пагинация документов и порядок участников](DOCUMENT_OPEN_0.27.md#списки-документов-и-участники-дела). Повторная проверка дала совпадение всех 39 страниц.

Основной автоматический набор: 514 тестов прошли, ошибок нет; 111 отдельных интеграционных сценариев не запускались обычной командой тестирования.

После перезапуска Rust 37 совпавших страниц повторно проверены восемью параллельными клиентами. Главная, настройки и `d/hdoc` открываются; отсутствующий документ по-прежнему возвращает 404.

Это проверка арифметики с `null`, а не всей семантики KS. В более широкой диагностике выявлены различия преобразования строк, унарных операций, сравнений и побитовых операций. Эти группы требуют отдельной доработки и не входят в исправление.
