# Регистрация пользователей в 0.21

Страница: [`/99?createnewuser&`](http://localhost:8070/99?createnewuser&). Используется штатная форма из `spdas.dbs`: выбор сотрудника, новая регистрация и изменение карточки. Отдельная форма Rust не подменяет её.

## Что исправлено

При выборе сотрудника возникала ошибка `List area invalid`. Скрипт создаёт список области «Пользователи» именно в базе `UserBase`. Интерпретатор теперь разрешает имя области по схеме указанной базы: одноимённая область основной базы имеет другой номер.

Для сохранения понадобилась поддержка старого формата DB40 6.12 в пользовательских томах. Реализованы запись карточки, индексы полей, список присутствующих объектов и словарный индекс логинов. Словарные блоки сохраняются в формате `S`, который требует kodweb. Успешное чтение тех же данных в Rust само по себе не подтверждает совместимость: его модуль чтения допускает больше отклонений от формата.

Штатный скрипт связывает три записи:

| Запись | Хранилище в контрольном комплекте |
|---|---|
| Сотрудник: ФИО, должность, код, контакты | Рабочий том основной базы |
| Учётная запись: логин, пароль, группы, приостановка и срок действия | `UserBase`, файл `ubase.db4` |
| Пользователь АИС: реквизиты и связь с сотрудником | Область «Пользователи» основной базы, файл `workbase/secure.db4` |

Пути в таблице описывают проверенный комплект. Код выбирает базу и область по подключению и схеме, а не по этим именам файлов.

Запись каждого тома использует существующий механизм журнала восстановления. Три вызова записи штатного скрипта не являются общей транзакцией: если поздняя операция завершится ошибкой, предыдущая может уже быть сохранена.

## Проверка на полном комплекте

Проверена синтетическая учётная запись типа «Специалист», группа «Работник», первая инстанция.

| Сценарий | Результат |
|---|---|
| Выбор сотрудника через классификатор в браузере | Карточка открывается без ошибки |
| Создание и изменение ФИО, примечания, кабинета и телефона | Поля сохраняются и читаются повторно |
| Сохранение примечания кнопкой формы в браузере | Показано подтверждение сохранения |
| Сохранение без смены пароля | Вход с прежним паролем работает |
| Смена пароля | Новый пароль принят, старый отклонён |
| Повторный логин или код | Штатное сообщение об ошибке; повторная регистрация отклонена |
| Попытка регистрации от обычного пользователя | Доступ запрещён |
| Карточка, созданная Rust, открыта и изменена в kodweb | Все проверенные поля прочитаны; изменение сохранено |
| Изменение kodweb прочитано Rust после перезапуска | Поля и вход с новым паролем работают |

Для двух пользовательских томов дополнительно сравнены индексы после создания и переименования записи с результатом kodweb; после удаления восстановилось исходное содержимое словарного индекса. Проверены все 527 существующих логинов контрольного `UserBase`: разбиение на слова совпало с сохранённым индексом. Существующие карточки при этой проверке не изменялись.

## Как изменить группы или отключить вход

1. Откройте [администрирование пользователей](http://localhost:8070/users?users), найдите логин и откройте карточку.
2. Для изменения прав отметьте нужные группы и нажмите «Установить». Можно выбрать несколько групп.
3. Для запрета входа установите **«Приостановлено»** и нажмите «Установить». Чтобы вернуть доступ, снимите эту отметку и сохраните карточку.
4. Поле **«Доступ разрешен до»** ограничивает срок действия учётной записи. Истёкшая дата запрещает вход; очистка даты убирает это ограничение.

Галка **«Действующий»** в `/99?createnewuser&` относится к карточке сотрудника. В проверенном kodweb и в Rust её снятие **не отключает вход**. Для прекращения доступа нужна приостановка учётной записи в `/users`.

## Группы и права: сравнение 22 ноября 2026 года

Созданы 21 тестовая учётная запись — по одной для каждой группы контрольного комплекта. Для каждой проверены десять страниц: главная, `/99`, регистрация пользователей, `/users`, `/admin?status`, первичная регистрация, входящие документы, форма отпусков, настройки распределения и общие настройки. **Все 210 результатов совпали с kodweb**, включая отказы внутри HTML-форм с ответом HTTP 200.

| Единственная группа учётной записи | Главная и обе регистрации дел/документов | `/99` | Регистрация пользователей | `/users`, `/admin?status` | Форма отпусков |
|---|---|---|---|---|---|
| Администратор | Доступны | Доступен | Доступна | Доступны | Доступна |
| Работник; группа разблокирования документов | Доступны | Отказ | Отказ | Отказ | Отказ |
| Группа распределения исковых заявлений; поиск и исправление данных стороны | Отказ | Отказ | Отказ | Отказ | Отказ |
| Остальные 16 групп | Доступны | Доступен | Отказ внутри формы | Отказ | Отказ |

Таблица описывает установленную конфигурацию доступа. Группы распределения исковых заявлений и исправления данных стороны являются дополнительными: сами по себе они не дают входа в проверенные каталоги. Сочетание этих двух групп с «Работником» даёт вход в `/20a`, но не административный доступ. На другом комплекте списки разрешённых групп могут отличаться.

Доступ к странице не означает право выполнить любую операцию на ней. В Rust просмотр настроек распределения разрешён пользователям `/20a`, а сохранение параметров и дочерние операции требуют административного доступа. Эта дополнительная проверка записи сохранена. В форме отпусков действует отдельный список разрешённых сотрудников.

| Изменение или проверка | kodweb и Rust |
|---|---|
| Добавление администратора к «Работнику» через `/99` | Административный доступ появляется |
| Снятие администратора | Административный доступ исчезает |
| «Приостановлено» | Вход запрещён во все три проверенных каталога: `/20a`, `/99`, `/admin` |
| Снятие приостановки | Права снова определяются группами |
| Истёкшая дата / будущая дата | Вход запрещён / разрешён в пределах групп |
| Удаление всех групп | Вход запрещён |
| Несколько флажков групп в `/users` | Все выбранные группы сохраняются |
| Попытка обычного пользователя назначить себе администратора через `/99` или `/users` | Запрос отклонён; три пользовательских тома не изменились |
| 36 параллельных запросов администратора, работника и специалиста | Ответы соответствуют каждому пользователю; чужие права не перенеслись |
| Приостановка, записанная Rust, прочитана kodweb; затем обратная проверка | Запрет входа действует в обоих направлениях |

Снятие административных прав проверено на одном сохраняемом HTTP-соединении в обоих серверах: следующий запрос уже отклонён. Приостановка в Rust также действует на следующем запросе того же соединения. В проверке kodweb ответ главной закрывал соединение, поэтому для приостановки там подтверждён отказ при новом подключении. Завершение уже выполняющейся операции после отзыва прав этой проверкой не охвачено.

Исправлены две причины отказа записи в `/users`: маршрут не был включён в список разрешённых операций, а отдельный UserBase не считался доступным для записи из каталога без `BaseN/RedactN`. Запись теперь разрешена только для аутентифицированного `POST /users?users`; открытие формы через GET не даёт права записи. Повторяющиеся поля `grp` объединяются в список идентификаторов; повторные управляющие параметры по-прежнему отклоняются.

Во внутреннем наборе прошли 392 автоматических теста. Дополнительно проверены явное подключение UserBase для записи, сохранение групп и статуса на полном комплекте, чтение записей оригинальным сервером.

## Границы проверки

Поддержка записи старого пользовательского тома ограничена проверенной схемой скалярных полей. Она не означает готовность записи произвольных полнотекстовых документов DB40 6.12. При неподдержанной схеме или несовпадении профиля индекса возвращается ошибка.

Одновременная регистрация одинаковых логинов и кодов проверена отдельно в [0.21.1](USERS_CONCURRENCY_0.21.1.md); исправлены накопление контекстов базы и конфликт между двумя формами регистрации.

Другие должности, подразделения и все операции отдельных модулей требуют отдельных сценариев проверки. Проверка десяти страниц и перечисленных изменений не подтверждает все права группы во всех разделах АИС. NTLM и внешние источники аутентификации не проверены.
