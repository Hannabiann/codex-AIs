# Открытие атрибутов области P в 0.24

23 ноября 2026 года проверены все 153 области из штатного списка P на полном контрольном комплекте: 49 подключённых томов, около 194 ГБ. Для сравнения использован `kodweb.exe`.

## Объём проверки

| Действие | Количество на каждом сервере | Результат 0.24 |
|---|---:|---|
| Открытие первой страницы списка | 153 | Совпали номера и порядок объектов, значения элементов формы |
| Открытие формы создания | 153 | Совпали значения элементов формы |
| Открытие атрибутов существующего объекта | 335 | HTTP 200, совпали значения элементов формы |
| Всего запросов | 641 | Расхождений в проверяемых данных нет |

Существующие объекты выбраны из первых трёх строк каждой непустой области; таких областей оказалось 114. Это проверка всех областей, но не каждого объекта базы. При сравнении исключён только дополнительный токен Rust для защиты от сохранения устаревшей карточки. Порядок повторяющихся значений полей сохранён при сравнении.

## Найденные ошибки

До исправления Rust не открыл восемь карточек, которые открывал kodweb:

- Две карточки «Комментарии»: в текстовом поле есть встроенный объект, который не поддерживает HTML-рендерер.
- Две карточки «Справка»: текст содержит дескриптор ссылки.
- Три карточки «Нарушение сроков»: после текстовых объектов хранится дополнительная информация об оформлении.
- Одна карточка «Запрос ФНС»: присутствуют пустые поля типа «Сжатые данные».

Форма атрибутов использует текстовые поля только для показа размера. Теперь этот размер вычисляется отдельно от преобразования текста в HTML или RTF. Сохраняется штатное правило: учитываются текстовые объекты верхнего уровня; текст внутри таблиц в этот счётчик не входит. Это дополнительно проверено на трёх шаблонах реестров. Само содержимое и оформление поля не переписываются. Полная визуализация всех разновидностей встроенных объектов этим изменением не добавлена.

У пустого сжатого поля DB4 после нулевой длины сразу идут тип вложения и сведения о файле — блока zlib нет. Rust ожидал блок и принимал следующие байты за его контрольную сумму. Исправлены чтение и запись этого пустого представления. Для непустых блоков проверки контрольных сумм, длины и границ сохранены.

В 39 пустых областях Rust также показывал лишнюю верхнюю панель списка. Пустой результат теперь обрабатывается той же веткой формы, что и в kodweb.

## «Страна», «Содержание2» и ошибка 695

Открытие атрибутов работает независимо от разрешения сохранять изменения. Отказ проверки файла доступа `invalid attachment path component` исправлен в [проверке файлового доступа](STATCARD_P_0.24.md); исправление входит в эту сборку.

В контрольном комплекте kodweb показывает `old/classif.db4` как доступный только для чтения. При сохранении выбранных записей «Страна» и «Содержание2» он возвращает 695. В штатной библиотеке это `MP_X_NATIVE_NO_SAVE_VOLUME`: «Не удалось найти тома БД для сохранения документа». Это не ошибка открытия карточки и не общий запрет редактировать любую область P.

Настройка записи классификатора не включается автоматически. Сохранение и удаление во всех 153 областях в этот прогон не входили. Успешное изменение ЭИД и блокировка статкарты проверены отдельно в [протоколе записи](STATCARD_P_0.24.md).

## Проверки кода

В итоговой сборке 0.24 прошли 467 автоматических тестов и отдельное сравнение счётчиков десяти текстовых полей полного комплекта с kodweb. Проверены границы пустых сжатых полей, запись и повторное чтение записи с такими вложениями, дескрипторы ссылок, дополнительные данные оформления и текст в таблицах. Проверка выполнялась на Windows; запуск этой сборки на FreeBSD и Linux в неё не входил.
