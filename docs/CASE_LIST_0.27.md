# Фильтры, сортировка и переходы в списке документов: 0.27

В карточке дела работает штатная форма «Фильтр/Сортировка». Можно отобрать документы по типу, дате, идентификатору, наименованию и тексту; открыть документ из результата, перейти к соседнему, вернуться на свою страницу списка или к условиям поиска.

## Исправления

Форма строится обработчиком `find` из `spb.dbs`. Для её выполнения добавлены получение встроенного списка через DOM формы, упаковка параметров `PackingVars` и подготовленный SQL-запрос с привязкой к списку. Запрос к `KODEKS_DOCLIST` ограничен документами исходного списка и его контекстом базы. Выбор нескольких значений классификатора передаётся штатному KS как один набор значений.

`CONTAINS` по отдельному строковому атрибуту теперь ищет в этом атрибуте. В номере дела сохраняется значение разделителей: например, `1/2026` и `1/20` дают разные результаты. Пустой результат возвращает штатную форму с сообщением. Ошибочные выражения тоже обрабатываются формой, а не ответом 501.

Для сортировки списка исправлены пустые значения, длинные номера-строки и многозначные атрибуты. Контрольные значения показали, что kodweb сравнивает номер-строку с выравниванием числовой части до десяти цифр; длинный штрихкод поэтому нельзя сортировать как обычное число. Это правило применяется к списку документов отдельно от числовых условий SQL и записи индексов.

При сортировке по многозначному атрибуту один документ может занять несколько позиций. Kodweb убирает соседние повторения одного объекта, но сохраняет повторения, разделённые другими объектами. Счётчик при этом показывает число уникальных документов. Rust сохраняет такое поведение: в контрольном списке из 27 документов сортировка по содержанию даёт страницы из 20 и 9 строк, по основанию — из 20 и 8 строк.

Переходы сохраняют условия фильтра, сортировку и текстовый контекст. Ссылка содержит параметры запроса, а не весь объект конфигурации KS. Список восстанавливается при обработке запроса; он не зависит от того, какой исполнитель обслуживал предыдущую страницу. Возврат к списку вычисляет целое смещение страницы.

## Проверка

Сравнение выполнено 25 ноября 2026 года на копии полного комплекта с 49 объявленными томами. Основной сценарий — дело с 27 документами из текущих и архивных томов.

| Проверка | Объём |
|---|---|
| Совпадение ответов | 668 из 668 по проверяемым статусам, тексту, порядку документов, параметрам фреймов и вариантам выбора |
| Сортировка | Все 302 варианта, доступные в штатной форме этого списка |
| Отбор | Тип, несколько типов с И/ИЛИ/исключением, диапазон и границы дат, идентификатор, наименование, текст документа, пустой результат |
| Текст наименования | 33 выражения: части номера дела, регистр, маски, разделители, операции и ошибки ввода |
| Классификаторы | Все шесть кнопок выбора атрибутов формы |
| Переходы | Предыдущий и следующий документ, возврат на страницу списка и к условиям; обычный, обратный и отфильтрованный списки |
| Многозначные атрибуты | Повторные строки, счётчики, вторая страница и переходы с неё |
| Регрессия карточек | 47 ответов предыдущей серии, включая два других дела; восемь параллельных клиентов |
| Параллельные фильтры и переходы | 32 запроса через восемь клиентов сохранили содержимое, порядок и параметры переходов |
| Автоматические тесты | 531 прошёл; дополнительно прошёл тест сортировки на полной копии по сохранённым ответам kodweb |

Сравнивались HTTP-статусы, видимый текст после нормализации пробелов, порядок внутренних номеров, параметры фреймов и варианты выбора. Проверка выполнялась через HTTP; побайтовое совпадение HTML и визуальное совпадение в браузере не заявляются.

У kodweb обнаружены два ошибочных перехода: на последней строке результата с повторными документами кнопка «Следующий» оставалась доступной и возвращала HTTP 500. Rust отключает переход за конец списка; возврат к списку и предыдущему документу остаётся доступен.

## Проверка на другом комплекте

Откройте дело с несколькими страницами документов. Отберите один тип и диапазон дат, откройте документ со второй страницы, перейдите вперёд и назад, вернитесь к списку. Условия и позиция страницы должны сохраниться. Повторите с несколькими типами и текстовым фильтром. При сравнении многозначной сортировки учитывайте отдельно число уникальных документов и число строк.
