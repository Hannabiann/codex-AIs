# Доступ к документам Word и почтовые штрихкоды

Проверка от 24 ноября 2026 года, версия 0.25. Использованы Word 2024 со штатной надстройкой `spdas.dotm`, `kodweb.exe` и полный контрольный комплект из 49 томов.

## Кнопка «База документов → Доступ»

Надстройка читает права через `/99?getpermissions`, а сохраняет через `/99?setpermissions`. Ошибка 501 возникала при чтении: служебная функция `AddToLog` вызывала `new File(null)`, который Rust отклонял. В kodweb такой вызов обозначает текущий каталог; проверка `isDirectory()` завершает журналирование без записи файла. Это поведение поддержано в Rust. Создание файла с пустым именем по-прежнему запрещено.

Сравнены пять последовательных изменений прав: доступ только текущему сотруднику, добавление второго сотрудника с полными правами, перевод его в режим просмотра, удаление из списка и очистка ограничений. Все 11 ответов чтения и сохранения совпали с kodweb побайтно.

Kodweb также прочитал права и штрихкоды, сохранённые Rust. Вместе с проверками состояний диапазона получено 16 совпадающих ответов.

В Word 2024 проверены открытие неподписанного документа из списка, вызов окна разрешений, сохранение текущих прав и повторное открытие. Ошибки 501 нет. Для подписанного документа штатная надстройка сама запрещает изменение прав до обращения к серверу; этот запрет сохранён.

## `/20a?regletters&`

Это раздел **«Регистрация диапазонов почтовых штрихкодов»**. Форма и обработчики загружаются из штатного KS в `spb.dbs`. Настройки индексов отправителя читаются из `config.db4`.

Исправлены три расхождения:

- Разбор JSON настроек использует регулярное выражение с символом `[` внутри класса символов. Для штатного KS это буквальный символ; Rust трактовал его как вложенный класс. Из-за этого существующие настройки считались отсутствующими.
- Форма отправляет фоновое задание с именем `regletters`, а имя скрипта в томе — `regLetters`. Проверка задания теперь учитывает регистронезависимые имена URL. Запись разрешена только известным режимам задания с указанным создателем и только на время исполнения соответствующего скрипта.
- После операции форма повторяет скрытые поля предыдущего диапазона: `prev_number_month`, `prev_number_first`, `prev_number_last`. При следующей отправке Rust возвращал `repeated control parameter`. Для этих трёх полей поддержано объединение через точку с запятой, проверенное на kodweb. Рабочий режим и текущие границы диапазона остаются одиночными параметрами.

На диапазоне из трёх свободных номеров проверены:

| Действие | Результат сравнения с kodweb |
|---|---|
| Регистрация | Совпали номера, контрольные цифры, срок действия и регистратор |
| Блокировка | Совпали наименование и статус блокировки |
| Разблокировка | Совпали очищенные поля блокировки |
| Изменение срока действия | Совпала новая дата у всех трёх номеров |
| Повторная регистрация того же диапазона | Оба сервера отклоняют пересечение; новые номера не создаются |

В браузере проверены штатная форма, полный список и перенос выбранного диапазона в поля формы. Операции используют исходные обработчики и подтверждения.

Дополнительно выполнена последовательность multipart-отправок из полученной HTML-формы: изменение срока → блокировка → разблокировка → повторная регистрация. Сохранялись все скрытые поля ответа, включая повторные поля предыдущего диапазона. Все четыре запроса завершились с HTTP 200; проверены значения трёх записей DB4 и сообщение о пересечении диапазонов.

## Полный список диапазонов

Режим «Диапазоны» выполняется в тяжёлой очереди. Форма регистрации и операции, изменяющие диапазоны, остаются у владельца очереди фоновых заданий.

Для этого режима SQL-курсор хранит список идентификаторов и поля только текущей строки. Он не ограничен миллионом строк или 4 МиБ суммарных значений. Повторные обращения к столбцам текущей строки используют один прочитанный документ. Остальные отчёты сохраняют прежний способ материализации SQL-результата; отложенное чтение включено только для полного списка почтовых диапазонов.

Тома для следующих 1024 строк определяются одним пакетным обходом индексов. Это устраняет повторный поиск каждого письма по всем томам после вытеснения кэша. Сами документы заранее не загружаются. Приоритет последнего тома, отметки удаления и сброс кэша при записи сохраняются.

На полном комплекте получена завершённая HTML-страница размером 522 757 байт за **157,8 с**:

| Раздел списка | Обработано записей |
|---|---:|
| Свободные | 1 753 |
| Заблокированные | 363 109 |
| С истёкшим сроком действия | 2 272 864 |
| Всего по трём выборкам | 2 637 726 |

Это число проходов по строкам трёх выборок, а не обязательно число уникальных писем: заблокированный номер может одновременно иметь истёкший срок. Три тестовых номера включены в свободный диапазон с изменённой датой. Расчёт выполняет штатная функция `parseSqlrToRanges`; её правила объединения номеров не заменялись.

Во время расчёта запрос прав Word завершился с HTTP 200 за 1,65 с при первом обращении к этому исполнителю; форма регистрации — за 0,24 с. Выборка не заняла очередь интерфейса.

У `kodweb.exe` полный список не завершился за десять минут наблюдения; на момент остановки запроса процесс использовал около 1,86 ГиБ частной памяти. Поэтому совпадение **всей исторической таблицы** с оригиналом пока не подтверждено. Сравнение операций регистрации, блокировки, разблокировки и изменения даты завершено на одинаковом небольшом диапазоне.

Автоматическая проверка на 1 000 001 строке подтвердила переход к последней записи и отсутствие чтения непосещённых документов. Полный набор проверок: **485 прошли, 0 ошибок**, 86 проверок с внешними данными запускаются отдельно. Повторные поля предыдущего диапазона проверены в обычной и multipart-форме.
