# Оба варианта формирования аншлагов в 0.23

В главном меню это два разных пункта. Настраиваемый аншлаг `/80/` открывает `/20a?anshlag&instancia=1&`. Обычный раздел `/81/` открывает `/20a?gen_anshlag&` — каталог из 23 форм контрольного комплекта.

Каталог обычных аншлагов берёт записи области «Реестр генератора отчетов» с признаком «Видимость = 5». Двадцать две кнопки ведут к `convertToExcel` с именем шаблона. Форма 16, «Аншлаг с группировкой по судьям и датам», запускает отдельный KS `dateandjudgeanshlag`. Название `convertToExcel` не означает, что результат обязательно Excel: проверенные аншлаги выводятся как HTML-таблицы для просмотра и печати; у генератора также есть вывод в Word.

## Очереди

| Операция | Группа исполнения |
|---|---|
| Каталог обычных аншлагов `gen_anshlag`, GET | Интерфейс |
| 22 шаблона через `convertToExcel` | Тяжёлая; этот маршрут был включён ранее |
| Форма 16 `dateandjudgeanshlag` | Тяжёлая |
| Расчёт HTML настраиваемого аншлага: `go=ok` или `go=OK` | Тяжёлая |
| Открытие настраиваемой формы, сохранение и сброс настроек | Владелец |
| XML-выгрузка настраиваемого аншлага | Владелец |

До этой проверки настраиваемый аншлаг и форма 16 занимали владельца и могли задерживать Word. Теперь их расчёты используют тот же пул, что и отчёты судебной статистики.

Открытие настраиваемой формы может обновлять сохранённые колонки при смене структуры шаблона. Поэтому оно, как и явные команды сохранения и сброса, остаётся последовательным. XML-выгрузка заменяет файл с общим именем `sudДДММ.xml`; она также остаётся последовательной. Эти операции могут задержать Word у владельца, но не занимают выделенного исполнителя интерфейса.

При выборе очереди учитываются параметры URL и формы в том же порядке, что при выполнении KS: поля формы перекрывают URL. Это проверено для GET, POST, кодированных имён параметров и альтернативного пути АИС. Неизвестные режимы, неразобранное тело и вложения не переводятся в расчётную ветку по одному лишь `go=ok` из URL.

Условия отбора и формат DB4 сохранены. Подробности настроек и XML: [Аншлаги и графики рассмотрения дел](SCHEDULES_0.22.md).

## Заголовки форм 6 и 8

В этих формах Rust выводил «Время засед ания» с пробелом внутри слова. При чтении форматированных фрагментов позиция следующего диапазона считалась от начала текста, хотя штатный генератор последовательно читает поток. Поэтому часть слова попадала в соседний фрагмент, а HTML-шаблон вставлял между ними пробел.

Исправлена позиция диапазона в адаптере форматированного текста. Заголовок теперь совпадает с оригиналом. Проверены также вложенные выделения и сохранение пробелов между словами; содержимое строк дел не изменилось.

В HTML оригинала два заголовка содержат непечатный маркер форматирования `U+0001`. При сравнении видимого текста он исключён; в [машиночитаемом протоколе](notices-0.23.json) отдельно сохранены признаки совпадения исходных значений и число таких маркеров.

Форма 13 («внешний») в kodweb не вернула ответ за 600 секунд; её сравнение с оригиналом остаётся незавершённым. В Rust она сформирована, а результат по всем судьям — 372 ячейки — совпал с предыдущей сборкой.
