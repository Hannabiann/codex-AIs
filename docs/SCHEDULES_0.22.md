# Аншлаги и графики рассмотрения дел в 0.22

В главном меню доступны два штатных раздела АИС:

| Пункт меню | Адрес | Результат |
|---|---|---|
| Формирование аншлагов — настраиваемая версия | `/80/` → `/20a?anshlag&instancia=1&` | Таблица расписания для просмотра и печати; при включённой настройке — XML |
| Формирование и публикация графиков банкротных дел | `/77/` → `/20a?bankrotanshlag&` | HTML-график с группировкой по судьям или залам заседаний |

## Настраиваемый аншлаг

Укажите дату или интервал, при необходимости выберите зал, судью, состав и коллегию. Кнопка «Сформировать аншлаг» открывает расписание; «Назад» возвращает к условиям. В результате есть ссылки на дела и заседания, счётчики за день и период, кнопка «Печатать».

В блоке «Настройка внешнего вида аншлага» выбираются столбцы и их порядок, размер шрифта и чередование фона строк. Доступны быстрый набор «Простой аншлаг» и выделение всех столбцов. «Сохранить настройки» записывает параметры в штатный текстовый объект области «Комментарии». Эти параметры читает и kodweb. Поведение «Очистить настройки» берётся из исходного KS; оно не означает удаление судебных данных.

Опция «Формировать xml-файл» использует существующий параметр АИС `XMLpath`. В заданном каталоге создаётся файл `sudДДММ.xml`, например `sud0110.xml`. При повторной выгрузке за тот же день файл заменяется. Каталог должен существовать и быть доступен серверу для записи. Если путь не задан, форма показывает штатное сообщение. Путь пока задаётся через общие настройки kodweb: изменение `XMLpath` через форму Rust ещё не реализовано.

XML — текстовый формат обмена данными. Файл содержит заседания, дату, время, зал, номер дела, стороны и судью. Для его формирования не нужны Excel и MSXML.

## График банкротных дел

Форма позволяет задать дату или интервал, судью, состав и кабинет, выбрать группировку по судьям либо залам. Можно менять набор и порядок колонок, сохранять настройки и возвращаться из результата кнопкой «Изменить условия». Для печати используется команда браузера и штатные стили страницы.

В проверенном KS раздел называется «Формирование и публикация», но отдельной команды отправки на внешний сайт в нём нет: результат — HTML-страница расписания. Отправка по FTP или в другую внешнюю систему в этой реализации не добавлялась.

## Что исправлено

Оба раздела исполняют формы из подключённого `spb.dbs`. Для сохранения настроек реализован `FromStream` текстового поля, для чтения — текстовый поток результата SQL. Запись использует общий механизм транзакций DB4.

В проверенном исходнике аншлага исправляются лишняя точка с запятой перед телом функции и сравнение ссылок на дела при сортировке. При одинаковом времени заседания порядок теперь совпадает с kodweb. Поправка применяется только к известному отпечатку исходника; другая редакция KS требует отдельной проверки.

XML-выгрузка разрешена в аутентифицированном запросе аншлага, только для имени `sudДДММ.xml` внутри настроенного каталога. Преобразование открытого файла в строку возвращает его имя, поэтому сообщение об успешной выгрузке показывает путь к файлу.

## Проверка на полном комплекте

Сравнение выполнено с обычным `kodweb.exe`, на полном комплекте из 49 подключённых томов. Сверялись значения ячеек и порядок ссылок на объекты, без изменяющихся служебных строк времени и версии сервера.

| Проверка | Результат |
|---|---|
| Аншлаг за 01.10.2026, все составы | Совпали 287 строк расписания и их порядок |
| График за ту же дату, группировка по судьям | Совпали 27 таблиц и 287 строк данных |
| Изменённые колонки аншлага; график по залам | Совпали значения, порядок колонок и строк; у графика 28 таблиц |
| Интервал 01–02.10.2026, один состав | Совпали оба результата, по 30 строк данных |
| Пустая дата 01.01.2035 | В обоих разделах совпал пустой результат |
| XML за 01.10.2026, один состав | Совпали все значения, элементы и порядок 26 заседаний; проверена повторная выгрузка |
| Настройки колонок | Сохранены Rust, прочитаны kodweb; проверено повторное открытие |

Через браузер проверены формирование, возврат к условиям, перестановка колонок, сохранение и сброс настроек. Регрессионный набор: 418 успешных тестов, 79 отдельных интеграционных сценариев не запускались в составе этого набора.

Проверка относится к установленным редакциям `anshlag` 52571 и `bankrotanshlag` 46911. Другие редакции скриптов, схемы судов и внешние системы публикации этими результатами не покрываются.
