# Проверка 0.16

[Сокращения и термины: отчёты, ETW, KS/DB, Excel и другие обозначения](GLOSSARY.md).

18 ноября 2026 года, Windows x64. Полная независимая копия комплекта одного суда: 753 753 файла, около 344,5 ГБ. Серверы запускались последовательно с проверкой процессов и порта. Обычный `kodweb.exe` использован для сравнения; `kodweb64` не потребовался. v2rayN не изменялся.

## Запись и восстановление

334 обычных теста прошли, 50 проверок с внешними данными исключены из обычного запуска. Девять отдельных проверок writer на копиях настоящих томов прошли: индексы, разбиение B-деревьев, записи/потоки, архивный текст, удаление, конфликт редакций и конкурентная запись. После последней оптимизации отдельно повторены конфликт и многократное сохранение, параллельные писатели и проверки восстановления.

Журнал проверен при обрыве после подготовки, во время изменения резерва, после его синхронизации, во время записи тома, после её завершения, при неполной отметке фиксации и после полной отметки. Проверены увеличение и уменьшение файла, частичная запись страницы, усечённый/повреждённый журнал, отказ записи резерва и постороннее изменение вне страниц журнала. В отдельной проверке дочерний процесс завершался на каждом из семи этапов; другой процесс восстанавливал ожидаемый образ. Это проверка аварии процесса и имитации сбоев записи, а не физического отключения питания накопителя.

Открытый читатель настоящего DB4 сохранял прежнюю запись при восстановлении и двенадцати параллельных сохранениях. Проверены 65 последовательных сохранений, сохранность остальных записей, резерв при фиксации и чтение старого образа. Проверена жёсткая ссылка между резервом и текущим томом: writer создаёт независимый резерв до изменения страниц.

В индексной проверке сопоставлены 15 вариантов на трёх томах: изменение, добавление индексных значений, вставка, физическое удаление и отметка удаления. Результат совпал с прежним полным построением по записям. Отдельно проверены 6007 ключей с разбиением фиксированных, строковых и ссылочных узлов.

## Оригинальный сервер после Rust

Очищенная сборка создала и отредактировала собственное тестовое дело, сохранила новый документ и две редакции RTF через `/99`. После остановки Rust команда `recover` не обнаружила незавершённых журналов. Обычный kodweb прочитал изменённые атрибуты, список редакций и оба RTF без изменения байтов; кнопка W вернула последнюю редакцию. Шесть объектов контрольного удаления отсутствовали. Их KOD проверены до переключения.

Шесть контрольных файлов исходного `C:\kodeks` не изменились. В копии проверены 24 файла: изменились только рабочий том, журнал действий и счётчики индексного каталога `config.db4`; байты его записей не изменились. Старые резервные копии поверх пользовательских данных не восстанавливались.

Интервал отчётов — 01.10.2025–01.10.2025, все судьи. Обе книги побайтно совпали с книгами 0.15, ранее сверенными с оригиналом по константам, листам и семантике формул. Новый годовой прогон в 0.16 не выполнялся. Кэшированные результаты формул оригинала не сравнивались.

Проверены главная, d/hdoc/doc, атрибуты, W, прямой предварительный список, настройки и статус. Один keep-alive-сеанс `/99` сохранил соединение между запросами; запрос без авторизации получил 401, следующий с авторизацией — 200.

Большое пользовательское дело не удалялось. Его полный рекурсивный предварительный список по-прежнему не проверен до завершения: здесь проверены параллельная работа и отмена. Linux/FreeBSD и другие комплекты этим прогоном не проверены.

## Публикуемый код

В публикацию входят 62 рабочих Rust-файла. AST-экспорт удалил 102 элемента, используемых только тестами, и не включил отдельные тестовые модули. Очищенная версия собрана через `cargo build --release --locked`; именно её бинарник использован для итогового HTTP-замера и проверки оригиналом. Проверки исследования, KS-выгрузки, базы, судебные документы и учётные данные в репозиторий не входят.
