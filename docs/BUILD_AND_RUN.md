# Сборка, запуск и перенос

В рабочей 0.28.3 добавлены [настройка числа исполнителей интерфейса и переносимый тест](PORTABLE_BENCHMARK.md). Для отдельного запуска с тестовыми настройками `KODEKS_SETTINGS_FILE` может указывать существующий абсолютный путь к файлу; без этой переменной используется обычный `codex-AIs.settings` рядом с EXE. Остальные переменные, включая выбор корня данных, адреса и порта, сохраняют свой приоритет.

[Сокращения и термины: отчёты, ETW, KS/DB, Excel и другие обозначения](GLOSSARY.md).

## Требования

Собирать следует текущим стабильным Rust/Cargo. Проверенная в рабочей среде версия — Rust 1.100.0, Windows x64 / MSVC. Нижний порог в Cargo — 1.88 из-за зависимостей сборки; отдельно на 1.88 выпуск не проверялся, используйте текущий stable. Нативная сборка Linux описана ниже, но этот выпуск не прошёл полноценный запуск записи на Linux. FreeBSD пользователь уже собирал и запускал; новые изменения требуют повторной проверки.

Для сборки копируйте весь репозиторий, включая `src/`, `Cargo.toml`, `Cargo.lock`, `build.rs` и `assets/`. На Windows сборочный скрипт добавляет иконку и сведения о версии в EXE. Нужен доступ к crates.io при первом скачивании зависимостей; после заполнения кэша возможен `cargo build --release --locked --offline`. Внешних C-библиотек для декодирования DB40, RTF и XLS проект не требует, системные C-компилятор и linker нужны, в том числе для зависимости `stacker` / `psm`.

## Windows x64

1. Установите [Rust через rustup](https://rust-lang.org/tools/install/) и [MSVC C++ Build Tools с Windows SDK](https://rust-lang.github.io/rustup/installation/windows-msvc.html).
2. Откройте новый PowerShell в каталоге исходников.

```powershell
rustup default stable-x86_64-pc-windows-msvc
rustc --version
cargo build --release --locked
.\target\release\codex-AIs.exe --version
```

Результат: `target\release\codex-AIs.exe`. Поместите его в корень копии комплекта. Настройки Rust находятся рядом с EXE, поэтому не копируйте неизвестный `codex-AIs.settings` с чужого сервера.

## Linux x86_64

Для Debian/Ubuntu, в учётной записи разработчика:

```sh
sudo apt-get update
sudo apt-get install build-essential pkg-config curl ca-certificates
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
. "$HOME/.cargo/env"
rustup default stable
cargo build --release --locked
./target/release/codex-AIs --version
```

Команда rustup приведена по [официальной инструкции Rust](https://rust-lang.org/tools/install/). Для другого дистрибутива установите аналогичный пакет компилятора/linker. Собранный бинарник обычно зависит от системной libc целевой машины; перенос между несовместимыми дистрибутивами лучше заменить нативной сборкой. Это не инструкция по кросс-компиляции Windows EXE из Linux.

Скопируйте `target/release/codex-AIs` в `/srv/kodeks`, дайте ему право исполнения. Сервису нужны права чтения полного комплекта, записи в предусмотренные тома редактирования, `DelObject`, каталог журналов и файл настроек. Не используйте `chmod -R 777`.

## FreeBSD

Используйте нативные Rust/Cargo и системный C-toolchain, затем ту же команду `cargo build --release --locked`. Примеры `env ... ./codex-AIs` ниже подходят для sh/zsh. Старые ошибки путей журнала и `MkDir` исправлены; если процесс запускается, а страница выдаёт ошибку, читайте stderr и проверьте именно версию бинарника, корень данных и права записи.

## Размещение и запуск

```text
kodeks/
├── codex-AIs.exe  (Windows) или codex-AIs (Unix)
├── config.db4
├── ... штатные DB4/DBS, kodeks.spl, XLS-шаблоны ...
├── old/          ← сохранить исходные имена и вложенность
├── workbase/     ← либо структура, указанная вашим config.db4
├── DelObject/    ← .kod создаются при удалении
└── Log-codex-AIS/
    ├── error.log
    ├── access.log
    ├── ... журналы KS ...
    └── OLD_Log/  ← ежедневные ZIP-архивы
```

С 0.28.1 достаточно запустить `codex-AIs.exe` двойным щелчком или выполнить `./codex-AIs` на Unix. Без аргументов запускается HTTP-сервер; явная команда `serve` продолжает работать. Приоритет корня данных: `KODEKS_DATA_DIR` → каталог исполняемого файла, если в нём есть `config.db4` → рабочий каталог. В версиях до 0.28.1 без переменной используется рабочий каталог. Для остальных команд, например `recover`, правила аргументов не меняются.

| Переменная | Назначение |
|---|---|
| `KODEKS_DATA_DIR` | Корень полного комплекта |
| `KODEKS_LOG_DIR` | Переопределение каталога журналов. В 0.29 по умолчанию — `Log-codex-AIS` внутри данных; также допустим отдельный каталог вне дерева базы |
| `KODEKS_HOST` | Явное переопределение адреса. В 0.28.1 по умолчанию `0.0.0.0`; выбор «Только localhost» в настройках задаёт `127.0.0.1` |
| `KODEKS_PORT` | Явное переопределение порта. С 0.25.3 без переменной читается `Port` из `config.db4`, ветка `SOFTWARE\Kodeks\Web`; при отсутствии параметра — `8070` |
| `KODEKS_TRACE=1` | Дополнительная диагностика загрузки KS |
| `KODEKS_PROFILE=1` | Временное профилирование функций и запросов; для обычной работы не нужно |

В 0.29 сервер автоматически создаёт `Log-codex-AIS/error.log` и `access.log`. Журналы KS сохраняются в той же папке, архивы за прошлые дни — в `OLD_Log`. Срок хранения — 7 дней, настройка `log_retention_days` в `/admin?advanced`; 0 означает бессрочное хранение. [Формат, ротация и проверки](LOGGING_0.29.md).

Сначала `config.db4` регистрирует подключения; startup виртуального каталога исполняется при первом обращении. Поэтому открытый порт ещё не доказывает работоспособность `/20a/`. Неудачный startup кэшируется до перезапуска.

Источник порта указан в журнале запуска. Если `KODEKS_PORT` был задан ранее в окружении службы или терминала, он продолжает переопределять `config.db4`. Для изменения порта нужен перезапуск. [Проверка настройки и недоступных хранилищ в 0.25.3](STARTUP_0.25.3.md).

## Сеть и порт

В **0.28.1** откройте `/admin?advanced` (администрирование → установки → расширенные настройки):

- **Сетевые интерфейсы**: «Все IPv4-интерфейсы (0.0.0.0)» или «Только localhost (127.0.0.1)». Нажмите «Сохранить настройки Rust». Выбор хранится в `codex-AIs.settings` рядом с EXE как `listen_scope=all` или `listen_scope=localhost`. Отсутствующий параметр означает `all`.
- **Порт HTTP — общий с kodweb**: укажите число от 1 до 65535 и нажмите «Сохранить порт в config.db4». Запись идёт в штатный параметр `SOFTWARE\Kodeks\Web`, `Port`; сохранённое значение использует и kodweb.
- Перезапустите сервер. До перезапуска он продолжает слушать прежний адрес и порт; фактический адрес показан в форме и `/admin?status`. После смены порта измените адрес в браузере и настройки подключения Word.

Если заданы `KODEKS_HOST` или `KODEKS_PORT`, они имеют приоритет над соответствующим сохранённым параметром. Для управления через форму уберите такое переопределение из окружения запуска. Адрес `0.0.0.0` означает все IPv4-интерфейсы; в браузере используйте IP-адрес или имя сервера.

Порт сохраняется существующей транзакцией DB4 с журналом восстановления и резервным образом. Форма проверяет права администратора, токен запроса, диапазон порта и версию конфигурации. Если другой запрос изменил конфигурацию после открытия формы, потребуется открыть её заново. Выбор интерфейсов и порт сохраняются разными кнопками.

Проверено на Windows x64 и полной копии из 49 томов: запуск без аргументов из другого рабочего каталога; переходы `0.0.0.0:8070` → `127.0.0.1:8181` → `0.0.0.0:8282`; приоритет переменных окружения; отказ для неверного порта и устаревшей формы. Kodweb запустился на порту 8181, записанном Rust; Rust затем запустился на 8282, записанном kodweb. Проверка новых настроек на Linux/FreeBSD ещё требуется.

## Другой суд и другая ОС

Количество томов и их приоритет берутся из конфигурации, не из списка файлов контрольного суда. Переносите **весь согласованный комплект**, включая схемы, справочники, старые тома, словарь морфологии и XLS-шаблоны. Не переименовывайте тома для подгонки под примеры в документации.

На Linux учитывайте регистр имён и права файлов. Windows-специфические пути к сетевым ресурсам, обмену, логам, Word и внешним программам могут остаться в `config.db4` или KS. Команда `codex-AIs audit-local-paths <корень>` помогает локально найти такие настройки; её вывод не следует публично выкладывать целиком. Внешние интеграции не становятся переносимыми только от смены серверного EXE.

Другие версии схем, OID служебных форм и KS могут потребовать новых адаптеров. Часть поправок защищена отпечатками KS, но существуют и преобразования по имени формы и содержимому. Проверка на другом комплекте обязательна; [правила доработки адаптеров](DEVELOPMENT.md#инварианты-совместимости). Начните с протокола [TESTING.md](TESTING.md).

Если каталог журналов недоступен, проверьте права на `Log-codex-AIS` внутри базы либо задайте доступный каталог через `KODEKS_LOG_DIR`. Причина отказа выводится в консоль. Предупреждение `MainKey/record header mismatch for OID 25001508` в контрольном комплекте не блокирует запуск и не связано с журналами.

## Настройки и переключение серверов

`/admin?advanced` сохраняет UTF-8-файл `codex-AIs.settings` рядом с программой. Параметры: `connections`, `queue`, `header_seconds`, `body_seconds`, `write_seconds`, `history`, `workers`, `keep_alive_seconds`, `listen_scope`. По умолчанию: `64, 16, 10, 10, 15, 128, auto, 60, all`. Порт HTTP сохраняется отдельной формой в `config.db4`. Значение `workers=auto` выбирает 3, 4 или 6 исполнителей при запуске по доступным CPU; явно заданное число 1–32 имеет приоритет. В мониторе показаны выбранное число и причина. Старый файл с шестью параметрами читается с новыми значениями по умолчанию. К общей очереди добавлено по одному резервному месту для владельца и интерфейса при наличии соответствующих исполнителей. При 4 исполнителях и `queue=16` общий максимум ожидания — 18. Изменения действуют после перезапуска, предыдущий файл сохраняется с `.bak`. Сетевые таймауты не являются сроком исполнения KS.

Переключение: дождаться завершения изменяющих операций → остановить текущий процесс → проверить его завершение и освобождение порта → запустить другой сервер. После аварийной остановки Rust, перед запуском оригинала, выполните `codex-AIs recover <каталог данных>` и дождитесь успешного завершения. Не запускайте несколько серверов на одних томах одновременно. На Windows порт проверяют `Get-NetTCPConnection -State Listen -LocalPort 8070`, на Linux — `ss -ltnp`, на FreeBSD — `sockstat -46 -l`. [Журнал и восстановление](DB40_WRITES.md).

Отключение клиента отменяет его KS/DB-операцию. В мониторе сначала появляется «Отмена запрошена», после подтверждения исполнителем — «Отменено» с количеством завершённых записей DB4. Начатая атомарная запись завершается; отмена не откатывает прежние записи каскада. Не завершайте процесс принудительно вместо этой отмены. HTTP keep-alive применяется и к `/99`; `keep_alive_seconds=0` отключает его. Этот таймаут относится к простоям между запросами, а не к длительности отчёта. [Подробности](CONCURRENCY.md).

## Удаление и восстановление

Штатный KS создаёт `DelObject/<дата>/<корневой OID>/<OID>.kod` независимо от галки отметки удаления. Галка оставляет маркер в DB4, в том числе для скрытия архивной версии. При очистке ссылок связанные объекты сохраняются в KOD уже после их изменения. Это не полная транзакционная резервная копия.

Импорт находится в `/20a?createNewObject` → «Закачать .kod», прямой вход `/20a?ispravlenieForm&bkod=1`. В Rust он поддерживает просмотр атрибутов, выбор тома, восстановление внутреннего номера и потоков. Дополнительно доступно [пакетное восстановление 0.28](KOD_RESTORE_0.28.md): выбор редакций, конфликты, связанные файлы и сравнение с выбранным томом. Пакет фиксируется в одном томе. Исполняемые KS-формы и скрипты пока не импортируются. [Штатная форма и ограничения](P_AREA_0.22.md). KOD одного объекта не заменяет согласованный снимок всех томов для отката каскадного удаления. `.db4.codex-backup` — резервный образ отдельного тома, не история версий всей базы.

## Глубокие вызовы KS

Большие каскады могут превышать 64 вложенных вызова. Стек расширяется через [stacker](https://github.com/rust-lang/stacker), сохраняя тот же поток и порядок исполнения. Нельзя считать это обещанием поддержки любой архитектуры: проверьте поддержку целевой платформы у `stacker`/`psm` и повторите глубокий обход на своей ОС. В этой версии проверена Windows x64; Linux/FreeBSD ещё требуют такого испытания.
