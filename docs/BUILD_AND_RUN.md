# Сборка, запуск и перенос

[Сокращения и термины: отчёты, ETW, KS/DB, Excel и другие обозначения](GLOSSARY.md).

## Требования

Собирать следует текущим стабильным Rust/Cargo. Проверенная в рабочей среде версия — Rust 1.100.0, Windows x64 / MSVC. Нижний порог в Cargo — 1.88 из-за зависимостей сборки; отдельно на 1.88 выпуск не проверялся, используйте текущий stable. Нативная сборка Linux описана ниже, но этот выпуск не прошёл полноценный запуск записи на Linux. FreeBSD пользователь уже собирал и запускал; новые изменения требуют повторной проверки.

Для сборки достаточно `src/`, `Cargo.toml` и `Cargo.lock`. Нужен доступ к crates.io при первом скачивании зависимостей; после заполнения кэша возможен `cargo build --release --locked --offline`. Внешних C-библиотек для декодирования DB40, RTF и XLS проект не требует, системные C-компилятор и linker нужны, в том числе для зависимости `stacker` / `psm`.

## Windows x64

1. Установите [Rust через rustup](https://rust-lang.org/tools/install/) и [MSVC C++ Build Tools с Windows SDK](https://rust-lang.github.io/rustup/installation/windows-msvc.html).
2. Откройте новый PowerShell в каталоге исходников.

```powershell
rustup default stable-x86_64-pc-windows-msvc
rustc --version
cargo build --release --locked
.\target\release\codex-AIs.exe --version
```

Результат: `target\release\codex-AIs.exe`. Поместите его в корень копии комплекта. Настройки Rust находятся рядом с EXE, поэтому не копируйте неизвестный `codex-AIs.settings` с чужого сервера.

## Linux x86_64

Для Debian/Ubuntu, в учётной записи разработчика:

```sh
sudo apt-get update
sudo apt-get install build-essential pkg-config curl ca-certificates
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
. "$HOME/.cargo/env"
rustup default stable
cargo build --release --locked
./target/release/codex-AIs --version
```

Команда rustup приведена по [официальной инструкции Rust](https://rust-lang.org/tools/install/). Для другого дистрибутива установите аналогичный пакет компилятора/linker. Собранный бинарник обычно зависит от системной libc целевой машины; перенос между несовместимыми дистрибутивами лучше заменить нативной сборкой. Это не инструкция по кросс-компиляции Windows EXE из Linux.

Скопируйте `target/release/codex-AIs` в `/srv/kodeks`, дайте ему право исполнения. Сервису нужны права чтения полного комплекта, записи в предусмотренные тома редактирования, `DelObject`, каталог журналов и файл настроек. Не используйте `chmod -R 777`.

## FreeBSD

Используйте нативные Rust/Cargo и системный C-toolchain, затем ту же команду `cargo build --release --locked`. Примеры `env ... ./codex-AIs serve` ниже подходят для sh/zsh. Старые ошибки путей журнала и `MkDir` исправлены; если процесс запускается, а страница выдаёт ошибку, читайте stderr и проверьте именно версию бинарника, корень данных и права записи.

## Размещение и запуск

```text
kodeks/
├── codex-AIs.exe  (Windows) или codex-AIs (Unix)
├── config.db4
├── ... штатные DB4/DBS, kodeks.spl, XLS-шаблоны ...
├── old/          ← сохранить исходные имена и вложенность
├── workbase/     ← либо структура, указанная вашим config.db4
└── DelObject/    ← .kod создаются при удалении

codex-AIs-logs/   ← отдельная папка ВНЕ дерева kodeks
```

Примеры запуска из README задают корень явно. Если его не задавать, программа использует рабочий каталог (`.`). Одного помещения EXE в правильную папку недостаточно, если служба запускается из `System32` или `/`.

| Переменная | Назначение |
|---|---|
| `KODEKS_DATA_DIR` | Корень полного комплекта |
| `KODEKS_LOG_DIR` | Отдельный каталог журналов KS; 0.17 создаёт и проверяет его при запуске. Без переменной — соседний `<имя каталога данных>.codex-AIs-logs`. Не внутри данных и не их родитель |
| `KODEKS_HOST` | По умолчанию `127.0.0.1`; `0.0.0.0` — все IPv4-интерфейсы |
| `KODEKS_PORT` | По умолчанию `8070` |
| `KODEKS_TRACE=1` | Дополнительная диагностика загрузки KS |
| `KODEKS_PROFILE=1` | Временное профилирование функций и запросов; для обычной работы не нужно |

Логи KS и stderr процесса — разные потоки. Например:

```sh
cd /srv/kodeks
env KODEKS_DATA_DIR="$PWD" KODEKS_LOG_DIR=/srv/codex-AIs-logs \
  KODEKS_HOST=0.0.0.0 KODEKS_PORT=8070 \
  ./codex-AIs serve > /srv/codex-AIs-logs/server.stderr.log 2>&1
```

Сначала `config.db4` регистрирует подключения; startup виртуального каталога исполняется при первом обращении. Поэтому открытый порт ещё не доказывает работоспособность `/20a/`. Неудачный startup кэшируется до перезапуска.

## Другой суд и другая ОС

Количество томов и их приоритет берутся из конфигурации, не из списка файлов контрольного суда. Переносите **весь согласованный комплект**, включая схемы, справочники, старые тома, словарь морфологии и XLS-шаблоны. Не переименовывайте тома для подгонки под примеры в документации.

На Linux учитывайте регистр имён и права файлов. Windows-специфические пути к сетевым ресурсам, обмену, логам, Word и внешним программам могут остаться в `config.db4` или KS. Команда `codex-AIs audit-local-paths <корень>` помогает локально найти такие настройки; её вывод не следует публично выкладывать целиком. Внешние интеграции не становятся переносимыми только от смены серверного EXE.

Другие версии схем, OID служебных форм и KS могут потребовать новых адаптеров. Поправки известных скриптов применяются только при совпадении отпечатка; чужой изменённый текст автоматически не переписывается. Начните с протокола [TESTING.md](TESTING.md).

Если в 0.16 браузер сообщает `KODEKS_LOG_DIR is required`, остановите процесс, создайте отдельную папку журналов и задайте эту переменную в том же окне PowerShell перед повторным запуском. В 0.17 ручная настройка необязательна. При данных в корне диска или отсутствии прав на соседнюю папку задайте доступный каталог явно. Предупреждение `MainKey/record header mismatch for OID 25001508` в контрольном комплекте не блокирует запуск и не связано с журналами.

## Настройки и переключение серверов

`/admin?advanced` сохраняет UTF-8-файл `codex-AIs.settings` рядом с программой. Параметры: `connections`, `queue`, `header_seconds`, `body_seconds`, `write_seconds`, `history`, `workers`, `keep_alive_seconds`. По умолчанию: `64, 16, 10, 10, 15, 128, 4, 60`. Старый файл с шестью параметрами читается с новыми значениями по умолчанию. К общей очереди добавлено по одному резервному месту для владельца и интерфейса при наличии соответствующих исполнителей. При 4 исполнителях и `queue=16` общий максимум ожидания — 18. Изменения действуют после перезапуска, предыдущий файл сохраняется с `.bak`. Сетевые таймауты не являются сроком исполнения KS.

Переключение: дождаться завершения изменяющих операций → остановить текущий процесс → проверить его завершение и освобождение порта → запустить другой сервер. После аварийной остановки Rust, перед запуском оригинала, выполните `codex-AIs recover <каталог данных>` и дождитесь успешного завершения. Не запускайте несколько серверов на одних томах одновременно. На Windows порт проверяют `Get-NetTCPConnection -State Listen -LocalPort 8070`, на Linux — `ss -ltnp`, на FreeBSD — `sockstat -46 -l`. [Журнал и восстановление](DB40_WRITES.md).

Отключение клиента отменяет его KS/DB-операцию. В мониторе сначала появляется «Отмена запрошена», после подтверждения исполнителем — «Отменено» с количеством завершённых записей DB4. Начатая атомарная запись завершается; отмена не откатывает прежние записи каскада. Не завершайте процесс принудительно вместо этой отмены. HTTP keep-alive применяется и к `/99`; `keep_alive_seconds=0` отключает его. Этот таймаут относится к простоям между запросами, а не к длительности отчёта. [Подробности](CONCURRENCY.md).

## Удаление и восстановление

Штатный KS создаёт `DelObject/<дата>/<корневой OID>/<OID>.kod` независимо от галки отметки удаления. Галка оставляет маркер в DB4, в том числе для скрытия архивной версии. При очистке ссылок связанные объекты сохраняются в KOD уже после их изменения. Это не полная транзакционная резервная копия.

У оригинального kodweb импорт находится в `/20a?createNewObject` → «Закачать .kod», прямой вход `/20a?ispravlenieForm&bkod=1`. **В текущем Rust обратный импорт не реализован.** Для отката испытаний надёжнее остановить сервер и восстановить согласованный снимок всех затронутых томов и конфигурации. `.db4.codex-backup` — резервный образ отдельной записи, не история версий всей базы.

## Глубокие вызовы KS

Большие каскады могут превышать 64 вложенных вызова. Стек расширяется через [stacker](https://github.com/rust-lang/stacker), сохраняя тот же поток и порядок исполнения. Нельзя считать это обещанием поддержки любой архитектуры: проверьте поддержку целевой платформы у `stacker`/`psm` и повторите глубокий обход на своей ОС. В этой версии проверена Windows x64; Linux/FreeBSD ещё требуют такого испытания.
