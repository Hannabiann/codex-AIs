# Одновременная регистрация пользователей

Проверка 22 ноября 2026 года: полный комплект из 49 томов, синтетические сотрудники и учётные записи группы «Работник». Сравнивались обычный kodweb.exe 5.3.2.120, 32 бита, и codex-AIs 0.21.1, 64 бита. Для каждого сервера использован одинаковый исходный снимок данных.

## Результат сравнения

Запросы отправлялись по отдельным HTTP-соединениям с общим сигналом старта. Для одинаковых логинов, кодов и обоих реквизитов проверены пакеты по 2, 4 и 8 запросов, каждый размер трижды. Разный регистр логина проверен в трёх парах. Контрольный пакет — восемь разных пользователей.

| Условие | Запросов | Сохранено в kodweb | Сохранено в Rust |
|---|---:|---:|---:|
| Одинаковый логин, разные коды | 42 | 39 | 9 |
| Одинаковый код сотрудника, разные логины | 42 | 38 | 9 |
| Одинаковые логин и код | 42 | 31 | 9 |
| Логин отличается только регистром | 6 | 6 | 3 |
| Все реквизиты различаются | 8 | 8 | 8 |
| **Всего** | **140** | **122** | **38** |

В Rust каждая конфликтная группа дала одну регистрацию; остальные запросы получили штатное сообщение о занятом логине или коде. Ошибок HTTP 500/501 не было. В kodweb подтвердились дубликаты в самих томах: 55 повторных логинов и 51 повторный код сверх первых записей. Эти количества пересекаются, их нельзя складывать. Число дубликатов зависит от порядка исполнения; таблица описывает конкретный прогон.

Повторная отправка всех 140 форм не добавила записей у обоих серверов. Последовательная попытка зарегистрировать существующий логин в другом регистре также отклонялась у обоих: ошибка kodweb возникает именно при одновременной проверке и сохранении.

Дополнительные сценарии:

| Сценарий | kodweb | Rust 0.21.1 |
|---|---|---|
| Двум существующим сотрудникам одновременно присваивается один новый код | Обе карточки сохранены с одним кодом | Одна сохранена, вторая получила сообщение о совпадении |
| Восемь регистраций одного логина через `/users` | Созданы три учётные записи | Создана одна, семь отказов |
| Один логин через `/99` и `/users`, три варианта порядка отправки | В двух парах созданы две учётные записи | Во всех парах создана одна |

После дополнительных сценариев Rust сохранил 39 сотрудников, 39 связанных пользователей АИС и 42 учётные записи. Три самостоятельные учётные записи созданы через `/users`, который не создаёт карточку сотрудника. Повторных логинов и кодов нет; связи всех 39 карточек проверены. Оригинальный kodweb прочитал 39 карточек сотрудников, все 42 учётные записи и их группы; вход с каждой из 42 записей прошёл успешно.

## Исправления

В 0.21 временные объекты `DataBase` оставались в кэше идентичностей интерпретатора после завершения запроса. В длинной серии достигался предел 128 контекстов. Из 140 ответов 39 завершились ошибкой 501; фактически были сохранены 38 регистраций, хотя успешных ответов было только 24. Часть ошибок возникала уже при построении формы после записи.

В 0.21.1 после запроса интерпретатор находит контексты, которые ещё используются глобальными объектами, замыканиями, документами, списками и SQL-соединениями. Остальные контексты и их кэши освобождаются. База каталога и UserBase сохраняются. Проверены 1 200 созданий временных контекстов с обычным завершением и исключениями, а также 300 подключений и освобождений UserBase на полном комплекте.

Для `/users` добавлен конструктор `new Document(0, UserBase)`: нулевой OID означает новую запись в указанной базе. Право записи по-прежнему проверяется.

Штатная форма `/99` искала занятый логин только в области пользователей АИС. Учётная запись, созданная отдельно через `/users`, могла там отсутствовать. Дополнительная проверка UserBase выполняется до записи сотрудника. При изменении карточки собственная учётная запись определяется по сохранённой связи с сотрудником. Исправление формы применяется только к проверенному исходному KS по его контрольной сумме; иной выпуск скрипта требует отдельной сверки.

Маршруты `/99` и `/users` выполняются одним владельцем состояния KS: проверка и последующие записи другой регистрации не вклиниваются между ними. Остальные исполнители продолжают обслуживать выделенные им запросы. Это свойство проверенных маршрутов одного процесса, а не ограничение уникальности на уровне DB4 для произвольных внешних программ записи.

Прошли 397 автоматических тестов и отдельная проверка срока жизни контекстов на полном комплекте. Записи трёх пользовательских томов остаются отдельными операциями с журналом восстановления; общей транзакции между ними нет. Исправления не объединяют их в одну транзакцию.
