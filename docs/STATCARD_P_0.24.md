# Блокировка статкарты и область P в 0.24

Проверка выполнена 23 ноября 2026 года на полной независимой копии контрольного комплекта: 49 подключённых томов, около 194 ГБ. Kodweb и Rust получили одинаковые исходные данные. Формы отправлялись через HTTP с набором полей, который формирует штатная страница.

## Статистическая карточка

В проверяемой карточке заполнено недостающее поле госпошлины тестовым значением. После нажатия «Заблокировать» оба сервера сохранили блокировку, дату и пользователя. Повторное открытие показало «ЗАБЛОКИРОВАНА». Попытка изменить сумму в уже заблокированной карточке не изменила сохранённое значение.

Сравнение выявило два расхождения, которые не были видны по одному HTTP-статусу:

- Нулевое денежное поле Rust показывал пустым. Штатный KS проверяет наличие объекта `LongDouble`; в kodweb такой объект существует и при значении ноль. Rust ошибочно применял к нему правило для обычного числового нуля. Исправлена проверка логического значения; `0.00` сохраняется при открытии и отправке формы.
- Пустое скрытое поле перед отмеченной галочкой давало строку `;7` вместо `7`. Исправлено объединение этих полей в формах статкарт. Несколько непустых значений сохраняют порядок, а конфликтующие служебные параметры по-прежнему отклоняются.

После исправлений совпали все значения полей формы и записи статкарты в DB4, включая повторные атрибуты. Денежные значения сравнивались точно после декодирования: ноль может иметь разное двоичное представление показателя степени. Побайтное совпадение всего тома не требуется. Kodweb открыл карточку, заблокированную Rust, и показал сохранённое состояние.

## Редактирование в области P

`isSuperAccessEnabled` проверяет файл доступа через `mp_fileExists`. Недопустимый Windows-путь мог вызвать в Rust неперехватываемую ошибку среды исполнения. Теперь отказ проверки пути является исключением файловой операции: штатный `catch` в `mp_fileExists` обрабатывает его и продолжает обычную проверку пользователя. Ограничения чтения и записи за пределами разрешённых каталогов сохранены.

На Windows-копии открыты формы трёх областей; конкретная ошибка пути дополнительно проверена изолированными тестами отклоняемых имён и внешних файлов. Запуск этой сборки на FreeBSD в данный прогон не входил.

| Область | Проверка изменения и повторного открытия |
|---|---|
| ЭИД | Оба сервера сохранили новое наименование. Значения всех атрибутов DB4 совпали; kodweb прочитал запись Rust |
| Страна | Запись находится в `old/classif.db4`. В подключениях контрольного комплекта нет тома записи для этой области. Kodweb вернул ошибку 695, Rust — сообщение об отсутствии доступного тома записи. Данные не изменились |
| Содержание2 | Такое же ограничение классификатора и отказ без изменения данных |

Состав подключений зависит от комплекта суда. Исправление файловой проверки не делает закрытый классификатор доступным для записи.

## Дополнительные проверки

Прошли 463 автоматических теста и отдельное сравнение записей полного комплекта. Проверены обработка недопустимых путей без выдачи доступа, нулевой `LongDouble`, повторные поля формы и журналируемая запись. Суммовой отчёт по статкартам сохранил прежний результат: совпали все 156 ячеек контрольной выборки.

Открытие атрибутов затем проверено во всех 153 областях P. Результаты приведены в [отдельном протоколе](P_ATTRIBUTES_0.24.md).
