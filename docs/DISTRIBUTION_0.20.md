# Распределение судебных дел — 0.20

Страница `/20a?raspred_settings` формируется штатным KS из подключённой базы. Собственный редактор версии 0.19 удалён.

## Откуда берётся форма

В проверенном комплекте `raspred_settings` — именованный объект `730099159` в `spb.dbs`. Исходного текста у него нет: атрибут 3 содержит 81 413 байт скомпилированного KS. В нём находятся логика страницы, HTML и JavaScript. Общие библиотеки добавляют панель инструментов, стили `mp_css`, функции `mp_js` и элементы выбора классификаторов.

Kodweb исполняет этот объект и подставляет данные каталога, справочников и служебного документа «Настройка распределения». Внешний вид страницы не задаётся отдельной формой внутри EXE.

Rust теперь декодирует и исполняет этот же объект. Добавлены операции байткода, используемые данной формой: функции, вызовы хостовых методов, обращения к свойствам, условия, циклы и обработка исключений. Они используют существующие значения и хостовые API интерпретатора. Неизвестные инструкции возвращают ошибку; это не полная реализация всего скомпилированного KS.

Сохранены штатная панель, таблица отпускных правил, порядок полей, подписи, переключение зависимых строк и кнопка «Установить». Rust добавляет скрытые поля проверки формы и адаптер окон классификаторов для современного браузера.

| Кнопка оригинальной формы | Адрес |
|---|---|
| Изменение сложности | `/20a?change_difficult_katsp` |
| Установка категорий | `/20a?raspredkategory` |
| Настройка блокирования | `/20a?RaspredSettingsBlockedInnForJudges` |
| Восстановить КП судей | `/20a?restorekp` |

## Сохранение и таблица категорий

`PathObject.SaveState` сохраняет параметры каталога в `config.db4`. XML правил и списков доступа записывается штатным скриптом в служебный документ DB4. Запись использует проверку ожидаемых значений и существующий механизм восстановления. Между двумя этими публикациями нет общей транзакции.

Для конфигурации формата DB40 6.12 обновляются не только записи и B-деревья, но и отдельный блок `D` со списком номеров объектов. Kodweb использует этот список при отборе: новая запись без него читается по MainKey, но не появляется в штатном реестре. Создание и удаление параметра теперь изменяют список в той же публикации DB4.

Обращение к параметрам HTTP-запроса через свойства `Connection` теперь учитывает регистр так же, как kodweb. Снятый флажок не наследует старое значение каталога. Для существующего числового параметра сохраняется явный `0`: штатная форма понимает его как выключенное состояние, а запись и индекс её имени остаются на месте. После записи исполнители обновляют значения параметров. Форма, открытая до другого изменения настроек, возвращает HTTP 409 вместо перезаписи свежих данных.

Таблица категорий отправляет несколько значений с одним именем поля — номером судьи или состава. Раньше обработчик принимал это за повтор управляющего параметра. Для этой формы значения объединяются в список, ожидаемый штатным KS. Повтор `mode` и других управляющих параметров по-прежнему отклоняется.

Добавлены сортировка `List.Order` по массиву полей и создание пустого `LongDouble` перед присваиванием сложности. Принадлежность судьи рабочему разделу в редакторе категорий учитывает исторические записи классификатора, как на контрольной странице kodweb. Обычные SQL-запросы сохраняют прежние правила выбора актуальной записи.

Редактор блокирования читает и сохраняет `INNForJudges.xml`. Строки ИНН и названий остаются независимыми. Замена файла выполняется после полной записи и синхронизации; предыдущий файл сохраняется в `.bak`. Проверяются версия формы и токен запроса.

## Что проверено

- Сопоставлены таблица и элементы оригинальной формы, включая четыре перехода в подменю.
- Полная форма сохранена и загружена повторно без изменения списков доступа и отпускных правил. Все 25 флажков поочерёдно изменены, прочитаны повторно и возвращены в исходное состояние. Проверены изменение числового поля, отказ устаревшей форме и неверному токену.
- После перезапуска kodweb прочитал созданный Rust параметр в редакторе реестра и в форме распределения. Отдельно проверены изменение существующего значения и удаление нового параметра вместе с его номером из блока `D`.
- Отправлена вся таблица категорий: фильтры «Составов» и «Назначенные категории» отработали без ошибки повторного параметра. Отметка категории у судьи сохранена, прочитана повторно и снята.
- На контрольном комплекте совпала матрица из 93 судей и 315 категорий, включая 29 388 элементов выбора, их состояние и порядок.
- Проверены изменение сложности, сохранение блокировок и предпросмотр восстановления КП для одного судьи за один день.
- Регрессионный набор: 354 теста прошли, ошибок нет. Отдельный тест на копии штатного `config.db4` проверил создание, изменение, удаление параметра и отказ записи по устаревшему состоянию.

Массовое восстановление КП и автоматическое назначение судей по сохранённым правилам требуют отдельного сопоставления результатов.

## Отчёт Z22.1 и доступность интерфейса

Проверен `/20a?StatOtchet221`: период с 1 января по 21 ноября 2026 года, все составы. При четырёх исполнителях два одновременно запущенных отчёта завершились за 392,110 и 394,772 секунды. Получены два одинаковых XLS по 4 512 256 байт.

Во время расчёта каждые 15 секунд запрашивались главная, настройки и `/admin?status`. Все запросы завершились с HTTP 200: главная занимала около 20–50 мс, настройки — 30–84 мс, статус — 2–25 мс. Это отдельные выборочные измерения, а не гарантия предельной задержки при любой нагрузке.

Описанная блокировка интерфейса в этом прогоне не воспроизвелась. Изменения планировщика для её устранения в выпуск не заявлены.
