# Изменения

## 0.16

- Writer строит изменения из существующих индексных ключей; добавление и обновление без удаления ключей заменяют только затронутые ветви B-деревьев.
- Небольшие изменения публикуются страницами с журналом undo/redo. Прежний образ доступен открытым читателям в памяти; резерв DB4 обновляется изменёнными страницами.
- Автоматическое восстановление при открытии тома и команда `recover <каталог>` для восстановления перед переключением на оригинал. Большие изменения сохраняют замену полного файла.
- Проверены обрывы записи и завершение отдельного процесса на семи этапах, конфликты редакций, параллельные читатели и писатели. [Протокол](docs/DB40_WRITES.md).
- Удаление двух тестовых объектов: медиана 0,840 с против 5,018 с в 0.15; kodweb — 0,393 с. [Условия и все повторения](docs/BENCHMARKS.md).
- README и схемы описывают устройство, ограничения и измерения без рекламных оценок.

## 0.15

- Пул KS/DB с отдельными контекстами и кэшами, резерв интерфейса и очереди, единственный владелец Word/At. Число исполнителей задаётся в настройках Rust.
- Отключение клиента отменяет KS, индексные чтения и ожидание блокировок; начатая публикация DB4 завершается целиком. Статус показывает исполнителя и подтверждённую отмену.
- HTTP/1.1 keep-alive, HTTP/1.0 keep-alive по запросу, корректное сохранение pipelined-запросов и отдельная авторизация каждого запроса.
- Подготовка образа DB4 и fsync не удерживают блокировку метаданных читателей. Обратный индекс строится на одном открытом образе файла при параллельных сохранениях.
- Старые шестипараметровые файлы настроек совместимы. [Устройство и границы](docs/CONCURRENCY.md), [проверки и замеры](docs/VALIDATION_0.15.md).

## 0.14.1 — первая очищенная публикация для Git

- Снят общий предел количества инструкций KS для startup, форм, каскадов, фоновых заданий и отчётов. Явный небольшой лимит остаётся внутренним средством тестов; в опубликованных серверных сценариях он не задаётся.
- Убран предел 64 вызова функций KS: стек при глубоком обходе расширяется, порядок работы исходного скрипта сохраняется. Добавлен кэш обратных ссылок по полю для больших плотных областей.
- Сняты пороги 10 000 элементов массива и 4 МиБ обычного HTML-ответа. Поиск числового OID работает без временных строк для каждого индекса; удаление элемента и склейка разреженных массивов обходят только заполненные позиции.
- Повторный поиск OID в плотных числовых массивах использует ограниченный кэш индексов; добавление обновляет его, остальные изменения и конец запроса сбрасывают. Это ускоряет список уже посещённых объектов без изменения порядка обхода.
- Для точно известного `DeleteObject` выбор полей ссылок вынесен из повторного полного перебора схемы. Неизменяемые дескрипторы кэшируются по схеме, области и флагу всех ссылок; SQL и исходные ветви удаления сохранены.
- SQL и соединения используют общий неизменяемый снимок схемы, без глубокого копирования всех областей при каждом запросе. При изменении подключений снимок заменяется; ранее полученный остаётся согласованным.
- Область, название, том и проверка существования документа читаются из скалярного префикса без распаковки RTF/CTF. Метаданные отделены от полного объекта, сохраняются правила перекрытия томов, отметок удаления и незавершённых правок.
- Повторные обращения используют ограниченный кэш метаданных и узлов индексов. При записи читатели и связанные кэши сбрасываются; проверка типа и допустимого размера блока сохраняется.
- Исправлена таблица `/admin?status`: ID, адреса с портом, время и длительность не дробятся; длинные URL переносятся, таблица прокручивается по горизонтали. Размер истории показывает действующую настройку.
- Убран искусственный предел 256 динамических подключений томов; состав подключений определяется комплектом суда.
- Полные встроенные копии известных KS заменены SHA-256-отпечатками. Условия применения поправок сохранены.
- Подготовлены GPL-3.0-only, документация, иллюстрации и публикационная копия без тестов, судебных данных и диагностических материалов.
